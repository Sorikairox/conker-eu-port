## Focus 1: tooling, `argfix.py`
`tools/eu_port/argfix.py FUNC < draft.c` rewrites the callee prototype lines of an m2c draft from the **caller's asm** (`protocheck.parse_s/defuse`): for every `jal callee` it scans back to the previous call
(delay slot included) and takes the arity from the highest `a0..a3` written (+ untouched entry `a`-registers below it = pass-through) and from stack stores at `0x10(sp)..` (prologue saves of `ra/s/fp/a` excluded
by the prologue scan); `f12/f14` written -> leading `f32`, `mfc1 aN,fM` -> `f32` in a GPR, `lui/ori`/`li` constant -> `s32` even if m2c said `f32`/pointer. Other positions keep m2c's type. `--tail` also guesses trailing
pass-through registers up to the function's own parameter count. The call expressions in the body are padded (`argK` / `0`) or truncated to the new arity. Callees already defined in C, or only prototyped in a
header, keep the existing prototype (the draft's duplicate line is dropped: this alone fixed the `redeclaration of 'func_X'` CERR class); a different one-line prototype in the target file is removed with `//DROP`.
`m2cfix.py` runs it after declfix when `ARGFIX=1` (or `tail`).

Measured on the 189 pool5 drafts (`build_port/s50/dfx0` = declfix only, `dfx1` = + argfix, ranked.txt in each):

| bucket | declfix | + argfix |
|---|---|---|
| CERR | 96 | 77 |
| SIZE+-1 | 15 | 19 |
| SIZE+-n (n<10) | 52 | 63 |
| DIFFn | 19 | 21 |

`--tail` was no better (CERR 99) and is not the default. The gain is mostly CERR -> compiles; a handful of drafts got worse (`func_1505D5D0` SIZE+1 -> CERR: the corrected prototype is all-`f32` but m2c still passes
pointers). Limits: it cannot see a stale argument register (`func_1506BCC8`: `a0` held an address for an earlier `lw`, the callee takes no arguments), nor the f32-versus-s32 nature of a `lw`ed argument
(`func_150CE0C0` third argument is an `f32` local), nor the true arity of a callee at a stack boundary. Always read the asm of a SIZE+-n draft's calls.

## Pitfalls
- `m2c` pointer arithmetic (`T *p; p += K`) scales by `sizeof(T)`: three of the SIZE-1 drafts were this alone.
- Unused named locals do not take stack slots when nothing refers to them in memory (`s32 pad[2]` did nothing for `func_1505A250`), but they do when the function already spills: do not assume either way.
- I changed `func_150A29C8`'s header prototype for an experiment (`u8` -> `u32`) and reverted it; a header change needs `check_files.py` on everything.
