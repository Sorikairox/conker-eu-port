## Lessons
- **Same source line = one scheduling unit.** Two statements written on one line let IDO reorder their stores (`li t0,A; li t1,B; sh t1,+2; sh t0,+0`); on separate lines the stores keep source order. Try line joins (one `tryall` over all subsets of adjacent store groups) before any permuter barrier for store-order-only DIFFs.
- A permuter match should be bisected: here `arg0 += 0;` and `sp.u3C = b; sp.u3C *= ...` were both unnecessary once the line joins were found (the permuter's output joins lines when it re-prints).
- Pool drafts named `sp.uXX` are often not one struct: check which offset the callee receives (`&sp.u30`) and whether low slots are reloaded named temps.
