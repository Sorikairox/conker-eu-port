## Recipes (also IDO_SHAPES section 16)
1. **Operand order of commutative/compare ops (the DIFF1 family: `bnel t2,a2`, `addu v0,t8`, `multu`)**: when BOTH operands are plain memory expressions (no named local), IDO
   emits them in REVERSED source order. A named local keeps source order. So: do not keep a `temp` for the field you want second; write the compare with the field of `arg0`/`pl` on the
   LEFT (`pl->unk0 == arg1->unk0`, `pl->unk0 == arg1->unk4.w`) to get `bnel arg1field, plfield`. `func_1519E874`: `(p[5] << 6) + *(s32 *)(*(u8 **)p + 0x1D4)` (reread, no local `v`) gives `addu v0,t8`.
2. **0x2D/0 handler family** (`or a3,a0` variants too): 2D arm without key temps (`if (*(s32*)(arg1+0) == *(s32*)(temp_v0+0))`, with `temp_v0 = (u8 *)arg0 + 0x28` computed BEFORE the `if`
   for the `or a3,a0` copy; arg1-field LEFT of a `u8 *` pointer variable but pl-field LEFT of a struct member access), `goto dummy_label; dummy_label: ;` at the end of the 2D arm, arm 0
   with `temp_v1 = *(s32 *)(arg1 + 0)` when the ref compares `v1,t1`; a top `cur = *(s32*)(arg0+0x28)` before the if when the ref loads it before the `beqz` (`func_151B1F54`).
   `func_151BCB54`: the header said `s32` return; an `s32` return keeps `v0` live at exit so IDO will not put `addiu v0,a3,0x40` into the `bne` delay slot: change the header prototype to `void`.
   `func_151D324C`: `goto dummy_label` after the callee call in arm 0 forces `b` + target-copied delay slot.
3. **`struct102 *arg0 + const`** is scaled by 0x40 (again): cast `(u8 *)arg0 + 0x110` (`func_151BEA68`).
