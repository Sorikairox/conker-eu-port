## 1. The fall: Conker walks off the edge of level 0x21's only floor. No port bug, nothing to fix in collision

### Reproducer

`port_work/p101/nb.sh NAME SECONDS [BUILD_DIR]` runs a node boot with the P97 pad script, so the stick is held from
15 s. The new `?p101col=N` diagnostic dumps the collision state the first N times record 0's floor query changes
from floor to void. `?p49walk` (P55) logs the query with an independent float reference over every triangle.

```sh
PORT_P101COL=2 PORT_P49WALK=3 PORT_P49EVERY=10 port_work/p101/nb.sh col1 20
```

### What the logs show (`fl1.log`, `col1.log`, `final.log`)

The player walks from the spawn point (27, 0, 27) towards -x / +z. The floor goes away where z passes 240:

| frame | x | z | query out | reference (all triangles) |
|---|---|---|---|---|
| 765 | -97.4 | 188.9 | 0 (floor) | (same) |
| 773 | -142.0 | 249.1 | -10000 | no triangle under (x, z) (`tri -2`, top -10000) |
| 805 | -341.5 | 518.1 | -10000, y -636 | none |

The frame where he leaves the floor depends on run timing: 773, 801 or 917 in this session's runs, about 805 in P99.
It is always at the same place, about (-142..-154, 249..268).

Collision state at the void (`[p101]` lines):
- Game mode D_800E0B94 = 1. The mode handler is D_8009018C[1] = func_151DECFC (wasm table index 0xCA8,
  `elem.txt`), which is gameplay. Level 0x21, entered at frame 715 through func_1501C710(6, 0x21) by the boot-screen
  timer in func_151DEBB4 (D_800E0EC0 >= 0x2C7).
- Area 0 (level DL D_800B0E00[0]): 288 triangles, x -240..240, y 0..0, z -240..240. That is a clean 12 x 12 grid of
  40-unit cells, 2 triangles each, which garbage data would not produce. So the vertices are read correctly
  (endianness and pointer relocation are fine).
- Areas 1 / 2 / 3: 0 triangles. D_800B0E00[1..3] are NULL. D_800DC320 = 0 world objects.
- All 4 areas are enabled (D_800894C0 = 1 1 1 1).

The level has no wall triangles and no objects, so there is nothing for the wall engine (D5E90_walls.inc) or the
object areas to stop him with. The C floor query (func_1510EED0 / func_150A3F50 / func_150A48C0 / func_150A5480)
agrees with the float reference over the whole table. That was already found in P55, and P55's synthetic sloped test
passes too.

Asm stubs first hit between the level load and the fall (`stk.log`, `?stubstack=1`):
- func_1509CBD4 at the level load.
- At the spawn frame 723 (frame 865 in `final.log`, where the run was slower), from the player-state dispatcher
  func_1506AD30:
  - func_1507E9A8, through func_1506D584 -> func_1507E7E4;
  - func_15141C0C / func_15146EE0 / func_151DA6F8, through func_15071DC8 -> func_15141A7C.
- func_1000F568 / func_10010344 (sound-effect emitters).

None of them is on the floor-query path: the query's inputs and outputs are already right.

### Verdict

- **Root cause:** the pad script holds the stick, and the player leaves level 0x21's 480 x 480 collision floor at
  |z| = 240. That floor is the level's only collision geometry: model 0, 288 triangles at y 0. He falls from there
  until the fall-death branch, and the respawn chain follows (scene level 0, then level 0x2C).
  - The old e35cc6a build falls the same way.
  - The floor query, the asm2c engines, the data and the relocation are not at fault. There is no port-side or
    game-C fix for collision.
- If the stick is left alone (`idle.log`: 60 s with `PADSCRIPT=0:0:0:0`), Conker stands at (27, 0, 27) on level 0x21
  for 37 s. Nothing else happens: no scene, no level change.
- **Still open (not a collision question):** whether the real game lets the stick move Conker on level 0x21.
  - That would mean mode 1 after the boot-screen timer, on a 480-unit wooden stage with no music (header song 0, see
    section 2) and no objects.
  - If level 0x21 should be an attract or intro level, a scene or demo controller is missing. Candidates: mode 0's
    handler func_151DE100, still asm and stored raw in D_8009018C[0], and the scene system's still-asm producers
    (func_15020920 & co.).
  - That needs a real N64 reference run, which this setup does not have.

## 2. Music: the level-start music function func_150000B0 is still an asm stub

### The chain

1. Each level load (func_15007B3C, game_34F20.c:227) calls func_150000B0 (game_2D4B0.c:26, GLOBAL_ASM, "maybe next
   year"; the m2c draft is commented below it).
2. The draft shows what it does:
   - It reads the level header D_800B0DF0: +0x2C s16 song A, +0x2E volume A, +0x32 song B, +0x30 / +0x34 / +0x36
     volumes, +0x38 mode (jump table jtbl_80091A30), +0x39.
   - It clears D_80041F04 / F08 / F0C.
   - It stops songs that are no longer needed, with func_1000DE1C(id, 4) and func_1000E46C fades.
   - It starts the level's songs with **func_1000D96C(song, ...)** and sets the volume with func_1000E46C,
     func_1000E40C and func_1000DF68.
3. func_1000D96C (C) queues the song record: func_1000B1B0 / func_1000B1FC, then func_1000B3D4 into D_800417B0[slot].
4. Every frame, func_1000D758 calls func_1000D2F8(slot), which calls **func_10008CE8**: it loads the sequence and
   starts it with n_alCSeqNew + n_alCSPSetSeq + n_alCSPPlay.

The music path from step 3 on is C and works: P99's `?p99snd` forced start plays in Chrome. **The only missing link
is func_150000B0.** As a stub it does nothing, so no level song is ever requested.

### Evidence (`?p101mus=1`: a wrap of func_150000B0 that logs the header, then calls the stub; `final.log`)

| frame | level | header +0x2C..+0x39 (memory order) | song A | volume A | mode +0x38 |
|---|---|---|---|---|---|
| 1 | 0x25 (boot screen) | 00000000 00000000 00000000 0000 | 0 | 0 | 0 |
| 722 | 0x21 | 00005DC0 00000000 00000000 0002 | 0 (none) | 0x5DC0 | 0 |
| 1015, 1511 | 0 (respawn scene) | 00604650 00000000 00000000 0002 | **0x60** | 0x4650 | 0 |
| 1431 | 0x2C | 00357FFF 00000000 00000000 0004 | **0x35** | 0x7FFF | 0 |

- So level 0x2C should start song 0x35 at full volume, and the scene level 0 should start song 0x60.
- Neither is requested. The only func_1000D96C call in 50 s is the floor ambient 0x15 (frame 2145, from
  func_1508000C).
- Level 0x21 itself has no song (0), so the first ~25 s are silent on N64 too.

### The other two candidates are not the blocker

func_10010154 / func_1000F568 / func_10010344 (init_EB00.c) are the positional sound-effect emitters (the
func_1000F6B8(x, y, z) family). They are first hit at frames 909-1265, during the walk on level 0x21 and at the scene, not at level start.
They matter for sound effects, not for music.

### Next step

Write func_150000B0 as readable C from `asm/nonmatchings/game_2D4B0/func_150000B0.s` (5-case jump table
jtbl_80091A30, about 0x400 bytes).
- Its inputs are all C or data: D_800B0DF0, D_800D2E4C, D_800BE9F8, func_1000B548, and the D_80041Fxx flags.
- Its callees are C: func_1000DEC4 / DE1C / D96C / E2F4 / E40C / E46C / DF68.
- So no stub producer blocks it.
