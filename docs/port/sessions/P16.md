## 1. The "random Unicorn segfaults" and the convert.py deadlock (fixed)

Root cause: **any `uc_close` in a process makes a later emulator segfault inside `emu_start`** (unicorn 2.0.1, aarch64
container). difftest dropped each trial's `Run`/`Uc` pair and called `gc.collect()`; unicorn's weakref finalizer then
closed the handle. func_1509BA04: every seed exit 139; same code with the Ucs kept alive (never closed): EQUIV.
Explicit closing between trials, or resetting and reusing Ucs (unmap + hook_del + flush_tb), did not help (reuse also
used 5–7 GB). This was also the P7 r7 / P15 convert.py deadlock: a `multiprocessing.Pool` worker killed by SIGSEGV
loses its task and `imap_unordered` waits forever (idle workers in `futex_wait`; the r7 pool in conkerdev-port is
still sitting there that way).

Fixes:
- `difftest.py`: **each trial runs in a forked child** that never closes its emulators (`gc.disable()`, `os._exit`),
  results come back pickled through a pipe. A child that still dies counts as an inconclusive trial
  (`[N trials crashed]` in the EQUIV line). `DIFFTEST_NOFORK=1` = old in-process behaviour. func_15035A04 seeds 1, 2
  (P15: exit 139) are now EQUIV.
- `convert.py --eval`: no Pool. Each function runs in its own forked child; results come back through a JSON file
  (no pipe to fill), the parent polls with a wall limit (`CONVERT_BUDGET*3+300` s), kills hung children, re-runs a
  crashed child with the next seed (`CONVERT_SEEDS`, default `1,3,5`), and reports `CRASH` with the best-so-far draft
  (snapshot `run/<f>.<n>.json.prog`) if all seeds die. Rows are written as they complete. The parent must not import
  difftest/unicorn before forking (children then segfault at once).
- Test: the 12 P15 never-run functions + func_15035A04 ran to completion; the full p16 batch (284 functions) finished
  in ~20 min with **0 crashes, 0 hangs of the pool** (4 per-function HANG rows = SIGALRM limit inside a child).
