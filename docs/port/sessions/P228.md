## 2. Multiplayer barrel menu trap (found and fixed, port tool)

First `mp.sh race` after the merges: **trap at frame 4442 in the barrel menu** (mode 3 level 1D): `func_150ADC50
(missing)` stub, then `RuntimeError: memory access out of bounds` in func_10004074 <- func_1510D984 (texture cache
ageing). `?infcheck=1` (the P37 [texid] wrap of func_1510D66C) showed ids 0x10A37720.. from **func_151EDBE8 <-
func_151ECE00** (barrel_menu_draw, port P226, game_eu_216470.c): `D_80090410 = (s32) D_88C;` / `(s32) D_87B` are
**absolute link symbols = texture ids 0x88C / 0x87B** (undefined_syms_auto.txt), but the port had them as zero data
stubs (wasm addresses). func_1510D66C stores the id in D_800DA37C before its range check, func_1510D984 then calls the
fatal handler func_150ADC50 (D_8003C8E0 = 0x0C000046) and walks the cache tables out of bounds.
Fix: `port/tools/vbe.py` ROM_ABS += `D_88C: 0x88C, D_87B: 0x87B` (same mechanism as D_89C / D_85D, P37). After the
rebuild: no [texid] line, the menu works, mode 0 level 0x33 at 7446.
Not a game-C bug (the C is right on N64); listed as a lesson: **new C that uses `D_<small hex>` link symbols needs a
ROM_ABS entry**. Remaining such symbol: `D_89810` (game_eu_1B1ED0.c shadow pass, `gSPMatrix(&D_89810)` = physical
0x00089810 = the identity matrix D_80089810) is still a zero data stub (port/stubs/data_stubs.c): the shadow view
matrix is all zeros in the port. Needs an alias to D_80089810 (vbe.py or data_stubs), not a constant. Not done here.
