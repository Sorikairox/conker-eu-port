## 1. func_1505C7D8 (attack hit test)

- Attack descriptor table (func_1505C1A4, 0x28 bytes per entry, local typedef `AttackBox`): +9 angle offset /
  box half length / 5, +0xA distance / box half width / 5, +0xC height, +0xE sphere radius / 4 or box forward offset
  (s8) / 5, +0x24 flags (0x80 box, 0x1000 may hit `unk124`, 0x2000 line of sight, 4 keep `unk21C`, 0x800 keep
  `unkD0`). Active entry = `unkD0 - 1`, re-read after every hit.
- Records: `D_800CC2D0[i - 1]` for i = 1 .. 3 (`unkF8 & 0x100`) or 1 .. 25. Target ellipsoid: radius `unkD2`, half
  height `unkD4`, centre offset `unkD6`; `unkD8` / `unkDA` shift it via func_1505D34C.
- m2c's record loop (`var_s4 - 0x32C` on an `s32 *`) is replaced by the array index.
- **UNVERIFIED:** in box mode the asm leaves the hit point x / z (stored to D_800CC2C0 / D_800CC2C8) and the sphere
  radius unset (stack slots); the C uses 0 (the difftest stack is zero-filled, so EQUIV says nothing).
- Surviving mutant: the 90-degree constant in the box frame angle (the sin / cos stubs ignore their argument;
  checked by hand: 0x42B40000).

## 2. func_150D5F7C (debris burst)

- Particle request on the stack: local typedef `DebrisParticle` (0x7C bytes, passed to func_15132FBC). The pad byte
  at 0x69 matters (u68 = 2, u6A = 1).
- Ray: from the old position along the normalised movement (func_15145128); a hit closer than 397 gives the surface
  basis (func_15144E80, normals flipped against the movement); else -movement basis (func_15146078) or (x, y, z) axes.
- D_800A0E00 (3 sprites), D_800A42F4 (count per type) and D_80089DC0 (sprite list per type) are real ROM data:
  pokes do not reach them, so the setups vary the type (func_15134070 result) instead.
- Float constants (0.0132f, 759.0f, 38.444f, 0.648f, ...) are m2c's reading of D_800A0E38..D_800A0E7C; the setups
  with RETF random floats are EQUIV, so they round-trip.
