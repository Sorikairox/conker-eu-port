## difftest fixes (tools/port/difftest/difftest.py)

| bug | cause | fix |
|---|---|---|
| `UC_ERR_EXCEPTION at 0x00000000` right after a stubbed call (UNSURE `func_150B0574`, `func_151DAE28`, many `fault only in cand`) | **Unicorn 2.1.x bug**: a `jal` whose delay slot is an FPU instruction (`swc1`, `lwc1`, ...) leaves stale delay-slot state. The callee's first block then runs as if it were in a delay slot and jumps to `btarget` = 0 (AdEL, intno 12). A minimal reproduction: replace the delay slot with a non-FPU instruction and the call works. Unicorn 2.0.1 does not have the bug. | difftest prepends a pinned **Unicorn 2.0.1** (`port_work/pyuc201`, gitignored) to `sys.path`. Install it once per worktree with `docker exec $CONKERDEV pip3 install --target /conker/port_work/pyuc201 unicorn==2.0.1.post1`. Override with `DIFFTEST_UNICORN=dir`. Without it, difftest silently uses the container's 2.1.x. |
| a callee's first basic block **executed** before the stub redirected PC (its stores counted as the function's writes, its loads could fault) | stubs set PC from a block hook, and the current TB still runs | stubs are now real code: `jr ra; nop` is written at every static `j`/`jal` target before the run. Each `jalr`/`jr rX` site has a code hook that stubs the runtime target and drops its cached TB. The block hook only logs and sets return values. |
| `sd`/`ld` (MIPS III) faulted, so every trial was inconclusive (`func_150A7D00`) | Unicorn MIPS32 CPU | `ld`/`sd`/`daddiu` are patched to `nop` in the mapped code, and a code hook on that address performs them. A 64-bit shadow per register is kept for ld→sd copies and daddiu. Other doubleword ops (`dsll32`, `dsrl`, `dsra32`, `daddu`, `ddiv`, ...) are **not** emulated: 20 asm files use them. |
| a candidate longer than the reference calls the function right after the reference (`func_150158D0` → `func_150159E8`): no stub could be placed there because the candidate's own code sat at that address | the candidate runs at the reference vram | if any static call target of the candidate falls in `[ref_end, cand_end)`, the candidate is relinked and run at `(vram & 0xF0000000) | 0x0F000000` (the same 256 MB jal region). Recursion resolves to the candidate's own run address. |
| `timeout only in cand` on loops bounded by random data | the candidate needs more instructions than the reference | the candidate gets 4× the instruction cap. A reference timeout is inconclusive (only the common call prefix is compared), as is a candidate fault after a reference timeout. |
| convert.py workers died (exit 137, the Pool then hangs forever) | each 2.0.1 `Uc` holds a large TB buffer, and Run↔Uc hook cycles are freed only by the cyclic GC | both emulators are released after every trial, followed by `gc.collect()` |
| hour-long runs on random function-pointer tables (`func_15013000`) | every new random `jalr` target creates a random page in Python | after 400 distinct stub targets, the run stops (inconclusive). Still slow: `func_15013000` is not done. |

Also: `difftest.sh` passes `DIFFTEST_BUDGET` into the container (before, it was ignored on the host).

**Note:** a `UC_ERR_EXCEPTION at 0x00000000` that remains is now usually a **real** candidate fault: an unaligned `lw`/`sw`
(address error → exception vector 0). For example, m2c's `*(s32 *)p = 0xFF` in a byte loop (`func_10005BE0`).

**Known gap (not fixed):** callee out-params are never written. So code behind `if (sp4C != NULL)` after
`f(&sp4C)` never runs (the stack is zero-filled). `func_151DAE28` is EQUIV but tests only its call. One idea: let stubs write a
deterministic heap pointer into aligned stack words passed as aN.

## Prototype conflicts

- **func_150AD9A0**: the callee asm reads only a0–a2, and the call site in `func_150A2280` never writes a3 (m2c pass-through). 3 args
  is correct. The NON_MATCHING body of `func_150A2280` (game_eu_CE6C0.c) now declares `s32 func_150AD9A0(s32, s32, s32)` and
  passes 3 args: EQUIV.
- **void vs s32**: the definition stays `void` (the asm's v0 is not a result). Matching files keep their `s32` prototype for IDO,
  and the NON_MATCHING build gets a `void` one:
  ```c
  #ifdef NON_MATCHING // the definition is void; one signature for wasm
  void func_10004074(s32);
  #else
  s32 func_10004074(s32);
  #endif
  ```
  Applied for `func_10004074` in game_eu_CA630, game_eu_1A9280, game_EF410, game_eu_AE110, game_57FA0, game_eu_1A6C30,
  game_eu_6CFB0, and game_eu_1B6590 (×3). Inside NON_MATCHING bodies (game_BC510 `func_150A7D00`, game_3B920 `func_1500E5C0`,
  game_476D0 `func_1510B5F0`) the prototype is simply changed to `void`: never nest `#ifdef NON_MATCHING`.
- **func_10007D14** was not a prototype problem: the body was wrong (now returns `OSThread *`, as all callers declare).
- Implicit-int callers (no prototype; for example init_3C40, init_1420, game_C8950) remain P3's list of mismatched calls.
- `protocheck.py` resolves `#ifdef/#ifndef NON_MATCHING` (the NM side) before it collects prototypes. Before this change it flagged the wrapped
  `#else` prototypes. It reports 0 problems.
