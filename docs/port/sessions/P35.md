# P35 / P35b: renderer accuracy on real level geometry (branch `port-web`)

P35 was stopped partway. It left about 320 uncommitted lines in `port/gfx/gfx.h` and `port/gfx/gfx_f3dex2.c`. P35b
kept that work, checked it, fixed what was wrong and finished it. All changes are under `port/gfx/`.

Run: `port/web/shot.sh OUT.png 'app=game&dlapprox=1&freecam=1&fcy=150&fcz=350&fcpitch=-25' 40000` (PROBE_ANGLE=metal).

## 1. G_CULLDL and G_BRANCH_Z (P35, kept)

- **`G_CULLDL` (0x03):** the DL ends when every loaded vertex in `vstart..vend` is outside the same clip plane:
  x or y against ±w, w ≤ 0, or z > w. The vertices are in the renderer's clip space, so freecam culls for its
  own view.
- **`G_BRANCH_Z` (0x04):** branches to RDPHALF_1 when the vertex's viewport-mapped screen z (16.16) is ≤ w1.
  Otherwise it falls through to the coarser DL.
- The frame summary counts `culldl N (M culled), branch_z N (M taken)`.
- **Not exercised yet.** Levels 0x21 and 0x25 send neither command (0/0). They should show up once models and the
  real visibility walk `func_150A5858` are drawn.

## 2. Lighting

### The level ucode is F3DEXBG, and its lighting was checked in the RSP code

- A frame runs two ucodes. The task ucode (text `0x800BEFD0`, ROM 0x31D70) has the data string
  **`RSP Gfx ucode F3DEXBG.NoN fifo 2.08`**. It draws the level. After the level, the DL switches with
  `G_LOAD_UCODE` (text `0x800C2990`) for the rest of the frame. The two differ in 4226 of the first 0x1400 text
  bytes.
- P35's overlay (text +0x1188, IMEM 0x12D8, 0x388 bytes) belongs to **F3DEXBG**. P35b disassembled it with
  rabbitizer (RSP), using `?udump=1` to dump the task ucode:
  - **0x12F4–0x13D4: model-space light directions.** The code transforms and normalises the dir at `rec+8` and
    stores it at `rec+0x18`. It does this for records `0x260 .. 0x290 + numLightsxSize`, that is the two lookats
    and point lights 0..M−1. It does not do it for record M.
  - **0x13D8–0x1420: eye position.** It computes `e = (pos + T@0x1F0) × S@0x1D0/0x1E0`. This confirms that Rare's
    `G_MOVEWORD 0x10` block is used as P35 decoded it.
  - **0x13E4: start colour.** `luv $v29, 0x170($9)` with `$9 = 0x150 + numLightsxSize` loads the **colour of
    record M** (`0x2C0 + 48 M`) as the accumulator. It has no direction and no normal dot.
  - **0x1424–0x1538: point lights, two per pass.** For each one it adds `col × min(1, K/16 / d²·…)`, with no normal
    term (`vlt` clamps it).
  - **0x1554: result.** `vmulf` gives `rgb = vertex rgb × min(1, c)`. A vertex whose flag high byte is below 0
    keeps its original colour.
- **So BG has no directional light and no normals.** The level DL sends `NUMLIGHT 0` and record 0 = white
  (`DC280C0A 105E0FF0`), so the level keeps its **prelit vertex colours**. That matches the floor's fade to black at
  the rim.
- P35's model read record M as a directional "sun" (n·d) plus an ambient at M+1. With BG's zero normals and the
  ambient image value (0), that model would draw **the level black**. P35b uses the BG model when the data image
  names F3DEXBG (`light_bg`). It keeps P35's sun/ambient model, unverified, for the other ucode (characters, with
  `G_MOVEMEM 0x0E` normals).

### DMEM seeding

- The RSP reloads the ucode data (DMEM 0x000..0x7FF) at task start and on every `G_LOAD_UCODE`.
- `dmem_seed()` copies the light records, `0x260..0x660`, the Rare block `0x1D0..0x200` and the normals `0x510`
  from the data image. In the image the light records are all zero, and the Rare block equals P35's `rare10_def`.
- So any record the DL does not send has the real initial value. It is no longer a guessed white.

## 3. Blender, fog and depth (P35, kept; one fix)

- **Blender:** the shader decodes othermode L's P/A/M/B selectors per cycle.
  - In 2-cycle mode, cycle 1 runs in the shader, with MEM read as IN.
  - The final cycle: without `FORCE_BL`, the output is P. With `FORCE_BL` and no memory term, the blend runs in the
    shader. When the final cycle reads memory, it maps to `glBlendFunc` (the A factor goes through alpha).
  - Coverage is approximated: `ALPHA_CVG_SEL` discards below 0.5, or below 0.125 with `FORCE_BL`.
  - Alpha compare: threshold uses the blend colour alpha; dither uses noise.
  - `ZMODE_DEC` uses a polygon offset.
  - `G_SETPRIMDEPTH` / `G_ZS_PRIM` write `gl_FragDepth`.
- **Fog:** with `G_FOG`, the RSP's fog factor replaces shade alpha, and the blender (`P = FOG, A = SHADE`) mixes in
  the fog colour. No tested level uses fog yet.
- **Fix (P35b): fill rectangles in 1/2-cycle mode.** They now run through the combiner and blender with shade 0 and
  s = t = 0, as the RDP draws them. Before, they were drawn as opaque prim colour.
  - Level 0x25 (boot) ends its frame with such a quad: `TEXEL0 × ENV`, an alpha blend. It covers the level, so the
    boot screen is black (`P35_l25_fade.png`). That is probably the real boot fade.
  - `?nofillrect=1` (diagnostic) skips these quads, so the level under them can be seen.
- **New (P35b): `G_SETSCISSOR`** maps to `glScissor`. The level frames use x 2..290, y 0..216. Before this, level
  geometry leaked past the overscan borders.
- The vertex shader clamps z to w. F3DEX2 does not clip at the far plane, so the far backdrop is kept.

## 4. Texture unit (P35, kept)

- **Exact decode, exact addressing.** Every tile is decoded at 2^mask texels when it has a mask, else at its tile
  size. The shader addresses texels with `texelFetch` and applies the RDP order per tile: clamp to the tile size,
  then mirror, then mask (wrap). Each tile has its own shift; the shift is no longer folded into the vertices.
- **Filter:** the RDP **3-point filter** with 5-bit fractions is the default, used for `G_TF_BILERP`.
  - `?filter4=1` uses 4-tap bilinear; `?filter0=1` uses point sampling.
  - Copy mode and `G_TF_POINT` use point sampling.
  - There is no half-texel shift; the RDP samples texel i at s = i.
- **LOD:** when `G_TL_LOD` is on in 2-cycle mode, the shader computes lod = texels per N64 pixel (from
  `dFdx`/`dFdy`, scaled by cimg/canvas).
  - The tile is base + ⌊log2 lod⌋, up to `tex_level` and at most 4 bound tiles.
  - The fraction is `LOD_FRACTION`.
  - Sharpen/detail only set the fraction under magnification.
- `P35_l21_point.png` (point filter) shows the floor's CI8 32×64 texels. The planks run continuously across
  triangle seams and the texel grid is aligned. In `P35_screenshot.png` (3-point) the floor is smoothly magnified.

**Plausibility:**
- **Level 0x21 (round wooden floor):**
  - The texture is aligned across seams, with no swimming and no z-fighting (two materials, 144 triangles each, no
    overlap).
  - Lighting is the prelit vertex colour: bright centre, dark rim. BG adds no directional term, so there is no
    lighting "direction" to judge.
- **Level 0x25 (boot):**
  - The level is a ±10000 plane at y = 0. Its RGBA16 32×64 texture has 1-bit alpha cut-outs, drawn as alpha cut-outs
    (`ALPHA_CVG_SEL`), over the blue fill colour. The blue/green colour is shading.
  - In the top view, the −z half of the plane is missing (blue). This is not explained; see gap 5.

## 6. Diagnostics added

- `?udump=1`: hex dump of task 10's ucode text (0x1800 bytes) and data, as `[udump] T|D off hex`.
- Logged once: `[ucode]` (the task ucode name and the text/data diff against the loaded one) and `[light] ucode data
  DMEM ...` (the seeded records).
- Under `dltrace`: `[light] off ...` (each `G_MOVEMEM 0x0A` record) and `[light] vtx` (the first 6 lit vertices).
- `?nofillrect=1` (see section 3). The `[draw]` line now shows the light model (BG/other) and the ambient.
