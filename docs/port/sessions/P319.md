## Boot trap (fixed)
P318's build (0c75ac3a) trapped at boot: `RuntimeError: memory access out of bounds` in free (func_10004074) called from
func_100014C4 (init_1420.c, level code reload) <- func_15007B3C <- game C main loop (`port_work/p319/intro_bad`-style
log in the first `port_work/p319/intro` attempt, overwritten by the good run).
Cause: func_10005B04 (tlb_area_init, game C since P285; it was an asm stub in the port before, so it never ran) stores
`area & 0x0FFFFFFF` (K0_TO_PHYS) in D_8003BE74, and func_100014C4 frees `D_8003BE74 | 0x80000000` and
`D_8003BE70 | 0x80000000` (PHYS_TO_K0). On the PC both are wasm pointers (0x10xxxxxx): the mask drops the 0x10000000 bit
and the or gives 0x9xxxxxxx.
Fix (port side, same pattern as P185 K0_ADD_SITES): `port/tools/vbe.py` K0_PHYS_SITES makes the `and 0x0FFFFFFF` in
func_10005B04 and the two `or 0x80000000` in func_100014C4 identity ops (`k0_phys=3` in the transform stats). No game C
change; default eu build untouched.
