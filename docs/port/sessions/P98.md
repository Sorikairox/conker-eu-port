## 1. `p98/protoasm_check.py` (prototype in scope vs. callee EU asm)

For every call in the NM-selected text of conker/src_eu to a function with no C definition in the NM build

FP param 1 after FP param 0 -> f14, doubles 8-aligned) and compared with what the callee's asm does
(`port_work/p93/eu.dis`):

  into func_150AD78C; `syscall` / `break` end a path). CFG from P79 arity_scan.py, tags: Ek entry word k (a0..a3 or
  stack word loaded from frame+4k), EF0/EF1 entry f12/f14, Mk word k moved into an FPR (mtc1 / lwc1 of the slot),
  R:f return of callee f. Moves, sp spills and reloads carry the tags.
- Word classes: F = FP use of an Mk value (except `cvt.s.w` / `cvt.d.w`, which is an int conversion: I), I = ALU
  operand, load/store base, branch, jalr; A = stored to memory (ambiguous); P = still in a0..a3 at a jal (resolved
  through the callee, recursive).
- Verdicts: FREG (register class differs at word 0/1: f12/f14 vs a0/a1), FLOAT (prototype f32, asm int), INT
  (prototype int, asm float bits), ARITY (asm reads words the call does not pass), RETF / RETI (return class),
  RETNONE (non-void prototype, asm sets neither v0 nor f0: info only).
- First version gaps found while checking rows: an mtc1 followed by cvt.s.w was counted as float (fixed: Mk tags);
  fall-through hand asm; `sw zero` gave an empty tag (v0 restored from such a slot looked unset).
