## 2. Cause (found, fix NOT browser-tested: out of budget)
- The scene's Conker track runs setup lists 0x3E / 0x40 / 0x4C at t=0 and 0x41 at t=150 (scene type 0xD b4 0 ->
  func_15083568 -> func_15030DE4 attachment records). With `?p69attach` / `?p81att` + the P271 DL log
  (`p271/p81_diag.patch`), Conker has 4 attachments (joints 4, 9 sub 65, 12, 9). Only 3 part DLs are drawn each frame:
  the record with **sub 65** (list 0x4C, attached to the attachment of list 0x41; cb 4, texture 0x0CBA) never draws.
- Its matrix comes from func_15031360 -> **func_15031C4C(obj, 65, 0)** (game_eu_5D910.c, owner **port**). The asm
  returns the first match when a2 == 0 (`beqz a2, return` before the decrement in the delay slot). The m2c C decrements
  first and returns only when a2 reaches 0, so with a2 = 0 it **never finds anything** -> no matrix -> the attachment
  is skipped. Every caller passes 0 (func_15031360, scene event type 0xD b4 2/3 in game_eu_51190).
- Exact fix (game C, owner port), in func_15031C4C's loop:
```c
        if ((temp_v0 == (*(u8 *)((u8 *)var_v1 + 0))) && (arg1 == (*(u8 *)((u8 *)var_v1 + 6)))) {
            if (var_a2 == 0) {
                return (u8 *) var_v1;
            }
            var_a2 -= 1;
        }
```
  (replacing `var_a2 -= 1; if (var_a2 != 0) { goto block_8; } return (u8 *) var_v1;`). Needs a difftest + registry row.

## 3. Second bug found on the way (same file, owner port)
func_15031D40 (attachment start effects): the asm has two jump tables, jtbl_800972F0 for kinds 0x82..0x90 and
jtbl_8009732C for kinds 0x37..0x5E. The C nests the low cases (0x37, 0x3D, 0x49, 0x5A, 0x5D, 0x5E) inside the
`(v - 0x82) < 0xF` branch, so they are dead: func_15100734 / func_151BDDD8 / func_15163BE8 / func_150D3870+5950 /
the +0x1A6 bump / obj+0x9C |= 0x6000 never run for those kinds. Rewrite as two plain switches; difftest.
