## 1. Dropped-return audit (`p179/voidret_scan.py`)

Bug class from browser P174: a C function declared `void` whose asm leaves a value in v0 / f0 that callers use.
The scan reads the default EU ELF (byte-identical to the ROM, so every caller's asm is ground truth, also for callers
that are matching C or still asm) and, for every `void` C definition the NM build compiles (NM branch and matching C;
`#else` twins of an NM body are skipped):

- callee side: backward walk from each `jr $31` (delay slots and likely branches modelled): is v0 / f0 last set by a
  non-call instruction (`set`, `near` = inside the epilogue), passed through from a callee (`pass`), or never?
- caller side: after each `jal F` (past its delay slot), forward walk over both branch arms: is v0 / f0 read before it
  is overwritten or another call happens (`read`), or does it reach the caller's `jr $31` (`ret`)?
- classes: SUSPECT = some caller reads v0 / f0; SUSPECT2 = a `ret` caller is non-void C and its own callers read v0
  (transitive); NEAR = v0 / f0 set in the epilogue but nobody reads it; RETPASS = tail call in a void caller only;
  TABLE = name used as a value and v0 set in the epilogue (none left; data-table dispatchers are covered by
  p162/tablesig.py, re-run: no entry in port-b files flagged).
- f0 `ret` paths are ignored (an int-returning caller leaves f0 stale; this produced 53 false SUSPECT2 rows before).
