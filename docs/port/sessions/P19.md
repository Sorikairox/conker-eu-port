## 7. Real-time freeze (P14)

Cause (by construction): timers are delivered only at retrace, inside `frame()`. A game thread that
polls a queue with `OS_MESG_NOBLOCK`, or busy-waits on `osGetTime`/`osGetCount`, never leaves its fiber,
so the main-loop callback never returns and the page freezes. Under `--virtual-time-budget` the same
happens, only the budget ends it. Reproduced once this session: the page stopped answering CDP
evaluate on a run that did not crash.

Fix (`pc_sched.c port_spin_check`): after 4096 consecutive empty NOBLOCK receives or clock reads by one
thread, deliver the due timers and yield; `port_sched_run`'s per-frame switch cap then returns to the
browser. **Not yet confirmed in the browser**: the two probe runs after the fix both hit the §6 crash
first. Node boots unchanged (143 gfx frames).
