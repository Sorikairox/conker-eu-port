## The func_150A49D0.s blob

- Hand-written asm with **two real entry points**: func_150A49D0(count, u16 ids[], force) transforms each world object's
  model vertices to world space (rotation from 3 angles via the asm sin/cos + scale + translation, or the camera-relative
  matrix D_800DC338[buffer] when kind == 0xFF; cvt.w.s rounding) and refreshes the per-triangle bounding boxes
  (D_800DC270 xz, D_800DC274 y); func_150A4ED4(area) selects an area's collision tables. func_150A4B50, func_150A4CC8,
  func_150A4CDC and func_150A4D78 are **labels inside func_150A49D0's loop**, not functions (nothing else references them).
- The fragment after func_150A4ED4 (`.L150A4F74` / `D_150A4FD4`) is **func_150A3F50's code** (its `beqz` targets it), so
  under NON_MATCHING it stays asm: `src_eu/nm_asm/func_150A49D0_tail.s` (GLOBAL_ASM inside the NM branch, with a dummy
  `glabel func_150A49D0_tail` because asm-processor needs one).
- **A latent NM bug is gone:** the blob keeps -sinA/cosA/etc. in f1-f13 across its jal to sin/cos (the hand asm sin/cos
  leave them alone). P24 made sin/cos C under NM, which may clobber them (IDO's ABI), so the P24 NM build computed garbage
  object vertices here. The only other callers of func_150AD780/func_150AD78C are IDO-compiled (ABI-safe).
- difftest cannot test this (its stubs return random f2), hence the whole-blob harness (both ELFs, the real sin/cos,
  hooked allocate_memory/free). Run in the container from `/conker/conker` after both builds:
  `PYTHONPATH=/conker/port_work/pyuc201 python3 ../tools/port/difftest/nmasm_blob49D0.py 300 1`.
