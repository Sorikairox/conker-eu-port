## 2. func_1504ADD0: pointer to a stack local

For an object index >= 4 (and < D_8008FD8C) the asm stores the address of a 6-byte zeroed local (sp + 0x48) in
D_800CC6A4 and leaves it there after returning. The C keeps that (`u8 pad[8]` local). difftest DIFFERs on it only
because the frame layouts differ (0x8067FEF0 vs 0x8067FEF8); `docs/port/sessions/p82/func_1504ADD0_fixsp.c` puts
the pad at the asm's address and is EQUIV on random 100 + all setups, and the mutants ran on it. In the port the
pointer dangles after the call as on N64: anything reading D_800CC6A4 outside func_150EDAF8 for those objects
reads stale stack (UNVERIFIED, browser).
