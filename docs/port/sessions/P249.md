## 1. Multiplayer stubs (browser P245)
- **func_150EDCC8 (game_eu_11AF60, Tank) `tank_update`: yes, it drives the tank.** It is the tank object's per-frame
  update (object update table at 0x8024642C in the ELF data, next to func_15054E00 / func_150CEC50; void, like its
  table neighbours). It reads the driver's pad (D_800BE748 entry: stick x -> steering +0x22B / heading +0x78, stick y
  -> throttle +0x44; buttons D_800BE728[0][player]: 0x8000 boost, 0x10 brake; D-pad flags turn the turret), calls the
  physics func_15052590, sets the track speeds (func_150EDBB8) and aims the turret (lock-on, camera view ray, auto-aim
  with lead). As a stub the tank had no throttle / steering at all: this is the "tank can't move" cause on the
  port side (port-b's 1E7CC0 / 161520 / 1FB080 stubs from P245 are separate).
  It calls the asm **func_150ED818** (tank_shell_aim_error, ballistic turret pitch helper), converted with it
  (producers before consumers). Every other callee already has C (func_150ACEA0 = D5E90 ray cast).
- **func_150BE050 (game_eu_EB860, Colors) `rideable_vehicle_update`: does not read a controller.** Per-frame update of
  a rideable object (same object update table, 0x80246444, between func_150EF328 and func_150EF204): eases +0x2E4,
  takes heading / turret pitch from the rider's aim part (+0x197 / +0x16C / +0x170), runs the physics
  (func_15052590) and its hit states (knock-back func_15052F9C, launch toward the first eligible player
  func_1505327C). As a stub the vehicle never moved / reacted; it is not the tank input path.
