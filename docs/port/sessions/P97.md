## 3. Sky quad t range (func_150D1D20 / func_15000AD0)

- func_15000AD0 (D_800B0DF0->unk8 == 2) builds the 4x256 gradient texture and 2x4 vertices: x/y +-0x6D6, z -1000,
  s 0x2000.
- func_150D1D20 is D_80089578[2], the draw table at 0x80089578: [0] 15110948, [1] 150FA030, [2] 150D1D20,
  [3] 15110B80, [4] 15112074.
- func_150D1D20 sets `t = ((top + 0x100) << 5) + trunc(arg4 * 81.0)` for the top pair and `((bottom + 0x1FF) << 5) + ...`
  for the bottom pair.
  - Asm: `0x42A20000` = 81.0, arg4 at 0x110($sp) = caller sp+0x10.
  - For level != 0x32 / 0x33 / 0x3F: top -0x13, bottom 0x65.
  - That is 237.0 .. 612.0 texels before scrolling. The tile origin is 256 (func_150954E4 0x100, 0x100), so rows
    -19 .. 356.
- The caller func_15110420 passes (x, y, z, A, B, C, handle), stack 0x10 / 0x14 / 0x18.
  - A = 360 - (view +0xC + player +0x388), wrapped to [-180, 180).
  - B = 360 - (view +0x10 + player +0x380), wrapped to [0, 360).
  - C = roll.
- The C names `yaw` / `pitch` are swapped: +0xC wrapped around 0 is the camera **pitch**, +0x10 in [0, 360) is the
  heading.
- So the t scroll is pitch x 81 / 32 = 2.53 rows per degree. P94's observed 292.06 .. 667.06 = 237 + 55.06 ..
  612 + 55.06, which is pitch 21.75 deg.
- **Verdict: the vertices are the game's own math. It is not a port bug** (no dropped argument, no float-int, no stub
  producer).
  - Rows past 255 are below the gradient's horizon (row ~167). The RDP clamps them to the "ground" green by design.
  - The scroll is linear in degrees while the projection goes as tan, so the horizon drifts from the true horizon at
    larger pitch (about 6 deg at 21.75 deg). That is in the game's own code.
- Calling through the pointer type `(Gfx *, f32 x6, s32)` while the definition is `(Gfx *, s32, s32, s32, f32, s32, f32)`
  is consistent on wasm: the port runs it and t matches.
- Not done: the black area above the green in P94's table-view shot.
