## 2. Implementation notes

- **guMtxF2L:**
  - The game's version is Rare's unrolled asm. It converts with `cvt.w.s`, which **rounds to nearest
    even** (FCSR.RM = 0), not the SDK C's truncating `(long)` cast.
  - The halfword stores (`e` at +0x20+i, `e>>16` at +i) are composed into whole 32-bit words: the even
    column goes in the high half. A word is a plain native store in vbe memory, so no `vbe_st16` is
    needed.
  - Out-of-range values saturate. The R4300 would raise an unimplemented-operation trap.
- **vbe.py `LIBC_VBE = ['bcopy','bzero','cosf']`:**
  - Game references get the same `@vbe.<name>` rename as the P4 `LIBC_CLASH` names. Emscripten's libc
    stays as it is for the PC layer.
  - `sigs.normalize` now also gets `@vbe.<name>` aliases of the sigdb entries for these 3 names, so the
    variadic `i32 @bcopy(...)` sites are still normalised.
  - Aliasing `LIBC_CLASH` too re-typed `_Litob`'s sret `lldiv` call, which added a link warning, so
    the alias is limited to the new names. Link warnings stay at 1.
- **Interrupts:** fibers switch only inside blocking calls, so masking never changes scheduling. The
  state is kept only so that callers that save and restore the mask see libultra's contract.
- License: ultralib has **no license file**, and its C carries SGI's proprietary-notice header. No
  ultralib code was copied; it was a behavioural reference only. See `port/ultra/LICENSES.md`.

## 3. Unit test `[gutest]` (port/boot/gu_test.c, expectations port/tools/gu_expect.py)

`python3 port/tools/gu_expect.py > port/stubs/gutest_expect.h` computes the expected values from the
N64 definitions, rounding every operation to single precision (bit-exact for `+ - * /`). The C test is
compiled like a game TU (vbe), so it calls the functions exactly as the game does. It checks:

1. `guMtxF2L` on edge values: ties at 1.5 and 2.5 LSB (round to nearest even), negatives, -0,
   fraction-only, -32768;
2. `guMtxL2F` (game C) → floats (bit-exact), then `guMtxF2L` back: an exact round trip. The script
   asserts that the inputs are exactly representable;
3. `guPerspectiveF` / `guPerspective`: game C with game `sinf`, PC `cosf` and PC `guMtxF2L`. The float
   matrix, the Mtx words and perspNorm are bit-exact against Python. Note that Conker's
   `guPerspectiveF` treats `aspect` as a second FOV;
4. `guMtxF2L` of a `guLookAtF` matrix computed in Python;
5. `func_150A7B80` = F2L(identity); `cosf` bit-exact on 10 inputs; fast sin/cos within 2e-6 of
   `sinf` / `cosf` over [-4, 4];
6. `bcopy` with source and destination at different alignments (and overlapping), and `bzero` at an
   unaligned start, all on vbe memory.

Result: `[gutest] PASS (0 failures)` in node. While writing it, the check caught a non-representable
round-trip input, which shows that it does detect mismatches.
