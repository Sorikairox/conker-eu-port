## 1. Finding: the "stale a1" quirk of func_1519AF14 was a table mix-up

P215 / P219 said asm func_1519AF14 dispatches D_8008FC48 = "EU 0x8008FFE8" (entry 0 func_151901F4) without setting
a1. The EU ELF disagrees: the dispatch `lui t9, 0x8009 / lw t9, -0x3B8(t9)` reads **0x8008FC48**, whose three entries
are func_1519CEB8 / func_1519CEE0 / func_1519CF08 (`s32 (s32)`, each just `func_1519D320(obj, k, n)`). So the a1 left in
the register is never read. 0x8008FFE8 is a different table (D_8008FFE8), dispatched by game_1FFF60's C with
`(node, &pos)` / `(child, &child->unk34)`: func_151901F4 always gets a real target.

Consequence: P219's PORT-only fallback in func_151901F4 (game_eu_1BAF40, `EFFECT_LAUNCH_TARGET`: aim at the node
itself, velocity 0) was wrong for the port; it is removed, both builds now use the target (the N64 NM body was
already reading it, so N64 behaviour and its difftest are unchanged). The comment is corrected.
