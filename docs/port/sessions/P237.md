## 2. Findings
- func_1508C600 (Total War / rail racer stub) is the line-of-sight test between two racers of func_1508CA14's
  pairing. Eye point: racer with state +0x84 set: y + 0.75 * s16 +0x114 (- 50 for state kind 9); record kind 0x1F:
  y + 80; when only the OTHER racer has +0x84 and D_80087664[difficulty] != -1: the s16 point +0x1A4..+0x1A8; else
  y + 40. func_150ACEA0 casts the ray; "seen" when nothing is hit or the hit is farther than the distance; then
  func_15087204 > 0 (wall) clears the "clear" result only. Rail +0x16C0 masks get bit b / a ("clear") and bit 16 + b /
  16 + a ("seen"). The record ids are masked with 0xFFFF0FFF, the mask indices are not (as in the asm).
- func_151EA4C8 (Total War stub, `passthrough`) is the two-team score panel: texture 0xD12 (32 x 32), 0xD13 (16 x 16,
  D_80090160 0x4000) or 0xD14 (barrel mode 8); returns `buf` unchanged when func_1510D66C gives 0x80000000. With
  `update` the scores are recomputed (0x6040: func_150859AC(team, 6); 0x100: per player func_150859AC(i, 3) >= 0 by
  team +0x128; else barrel rows +0x46 by D_800E1030) and stored as s16 in D_800E0ED0; the printf gets the full s32
  sums. Texture ids are literals (no D_D12 link symbols, P228).
- func_15160E30 / func_151B99B8 are D_8008B0F0 handlers (`s32 (struct225 *)`, return 1 or 0 as the dispatcher
  expects). func_15109390 (the third entry named in the brief) was already C (game_eu_1365E0, `s32 func_15109390(u8
  *)`, matched), nothing to do.
- func_151B99B8: the first draft cached the beam pointer (effect +0x1C) in a local. The asm re-reads it before every
  store, so when the beam record overlaps the effect the results differ (random trial 7 DIFFER at a learned
  pointer). The C now re-reads it (macro B9B8_BEAM); D_800AA948 is the literal -0.0066666668f (-1/150, read from the
  ELF).
- func_15160E30: the ray result buffer is a local `Ray_60E30` (hit object, t, x / y / z, +0x59 hit kind: 0 none,
  1 world, >= 2 object); brightness = clamp(scale * t, 0, 255) converted as unsigned like the asm.
- func_150C7E68 sits in the 3-word object callback records at EU 0x800891B0 (with func_150C7DE0 / func_150C7E30,
  both void C); func_151600E0 in the table at EU 0x8008B430 next to `void func_15160104(u8 *, s32)`. Neither has a jal
  caller.
