### Tail (func_1503BCAC / func_1503CE88, P70)

- It runs once per game frame (max 1 call / frame) on record 0 (id 01, Conker). The chain behaves as expected:
  - segment lengths are ~26 units;
  - `phase` advances while walking (anim 0x02: 287 → 155 → 348 deg);
  - idle sway re-picks `swaySpeed` / `swayAmp` (-12 / 72, -18 / 34, 11 / 73, ...); timer and fade work;
  - the reset after the level load re-roots p[0] at the new position.
- Chrome shows the tail bending sideways and following the walk (`P75_screenshot.png`, `p75/walk_36000ms.png`).
- **LATENT BUG (for the port branch):** game_eu_61AE0.c declares `void func_1503BCAC();` and calls `func_1503BCAC()` with
  no argument (func_1503482C). On N64, a0 still holds func_1503482C's arg0. In the port, sigs.py fills missing arguments
  with 0: `port/build/ll/game_eu_61AE0.c.v.ll` has `call void @func_1503BCAC(i32 0)`.
  - The `[p75] tail` log shows `arg0!=0 0`, so every call simulates record 0.
  - This is harmless while Conker is record 0 and the only object with an id in {0..4, 0x80, 0xB0}. Any other such
    record would move Conker's tail instead of its own.
  - **Fix on the port branch:** in func_1503482C pass `arg0` (prototype `void func_1503BCAC(s32)`). Check that it
    stays byte-identical, or put it under NON_MATCHING.
- **Same class elsewhere:** `p75/missing_args.txt` lists 18 call sites where a function that is now C gets fewer
  arguments than its definition, so the port passes 0. 13 of them pass no argument at all. Each one has to be checked
  against the asm: does the caller's register still hold a meaningful value at the `jal`? The worst:
  - func_15049350 (game_83300, 1 of 9 arguments);
  - func_15084000 (game_CB1C0, 1 of 4, 2 sites);
  - func_15131C7C (0 of 2);
  - func_1503BCAC (above).
