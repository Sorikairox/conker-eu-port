## 2. reverify.sh fixes (tools/port/reverify.sh)

1. **Setup fields lost to registry knobs**: `dt` ran `env "${envs[@]}" ...`, so a registry knob (e.g. func_15170648's
   random-phase `DIFFTEST_ARG=5=0|1|2`) replaced the same field of every setup -> 0 / 4 UNSURE. A non-empty setup field
   now wins. Rows affected: func_15170648 and port's func_151D75B0 (RET knob; re-check its setups).
2. **Named mutant setups only searched in the first setup file**: func_15177360's m7360b names setups of its second file
   (s7360b) and ran nothing ("invalid (=)"). Named setups are now looked up in every setup file of the row.
3. New knob **`CANDSED=file`**: `sed -f file` on the candidate (and the body layout) before each run, for test-only edits
   that must follow the current NM block (unlike `DRAFT=`); must keep line numbers.
4. New knob **`NR=N`**: random trial count for the row (env NR still wins). With NR=100 difftest needs 12 completed trials
   (`ok >= trials / 8`) but stops after 8 once the 30 s budget is used: slow functions (func_150C92B8, 8 trials) came
   back UNSURE although sessions recorded EQUIV at 8 / 16 trials.

`port_work/p244/mutfix.py DRAFT CURRENT MUTFILE OUT` rewrites `Ns/a/b/` mutants as `\#^<full draft line>$#s/a/b/`
when that line is unique in the current block (else the difflib-mapped line number), and checks that each rewritten
mutant changes the same lines as the old one did on its draft.
