## 1. ROM data: the room is the death tutorial, and it waits for the squirrel tail

`evtab.py ELF 22`: level 0x22 has exactly one level event, **0xCA "First Death"** (flags 20000072, no prerequisites).
Level 0x18 (the new-game level) has **0xBF "Introduction"** and **0xCB "Ha Ha Ha Your Dead"** (waits for BF).

Event 0xCA (ev_CA.txt), entry 1 (0x26) starts scene 1; entry 2 (0x3E, every frame) is a state machine on var0:

| state | waits for (native 5 = D_80088838 query) | then |
|---|---|---|
| any | `0x1000(5)` = func_1509CBD8 case 5 = D_800C3A92 (debug skip) | print "SKIPPED DEATH", sub 0x180 (leave) |
| 0 | `0x1001(1)` = func_1509CBD8 case 1: scene 1 no longer playing (D_800C35EA == 0 or scene != 1) | var0 = 1 |
| 1 | `0xE019(4)` = func_1509DFCC case 0x19 / 4: **no node in lists D_800A6440 = {0x36, 0x4C, 0x5B} (both groups of D_800DD280) has byte +0x48 == 2** | print "LIFE COLLECTED", start scene 4 (`0x1004` native 6 = func_1509C850), var0 = 2 |
| 2 | `0x1004(1)`: scene 4 done | sub 0x180: native6 0x2000(3, 0x64), read 0x50CA vars 0x21 / 0x20, native6 0x5000(7, ...) = **level change back to the saved level**, 0x50CA(1) |

Entry 4 (0x11A): 1000-step countdown, then "Sent to HELL but task was done - Tell Shawn" and the same 0x5000 exit.
Lists 0x36 / 0x4C / 0x5B share one class in D_8008B848 (update func_15157840, draw func_15157990, game_eu_185050.c):
the collectible; in the room it is one node at (-421, 170, -21) with +0x48 = 2: **the squirrel tail hanging under the
gargoyle on the pillar** (P165_2 / P174_1). The gargoyle / "tongue" are scenery; no context action (event-script 0x45)
is involved, which is why ctx+0x7B stayed 0 in P165 / P171.
Scenes (sc22_*.txt): scene 1 (1950 ticks) and 2 = Gregg's intro (scene 2 chained by the scene itself at 12441), scene 4
(600 ticks) = the revival after "LIFE COLLECTED".

Event 0xBF (ev_BF.txt): scene 1 -> (1001 done) **scene 3** (`0x1003`, arg 0x1D) -> scene 0x14 -> scene 2 -> sub 0x1E8
(0x50BF / 0x5000 actions with level 0x29) -> done (then CB may run).

## 2. Runtime (node evA, no fix): two converted functions answer wrong

`?p174ev` wraps func_150AE5F8 (native 5) / func_150AE60C (native 6) / func_150ADFD0 (VM, to tell the events apart) and
prints the C answer next to what the asm would answer.

1. **func_1509CBD8** (game_eu_CA060.c, NON_MATCHING m2c from port P15): declared `void`, every `return` lost; the asm
   returns 0 / 1 per case (jtbl_8009E828: case 1..6, case 5 = D_800C3A92). Through the s32 table the port gets 0 for
   every scene query (`[icall]` converts the void result to 0). Effects seen:
   - frame 2140 (menu event C8): `1001(2)` C 0, asm 1.
   - **frame 10725** (end of the intro's scene 1, level 0x18): BF asks `1001(1)`, C 0 / asm 1, so scene 3 is never
     started; Conker is left in the scene's position and dies falling (func_1507D4F8 at 10813, y -4759, evC with
     p61check) -> func_1501C710(1, 0x22): **the "first room" is reached only through this bug** (it is the death room).
   - **frame 18485** (Gregg's scenes over, player control): CA asks `1001(1)`, C 0 / asm 1: CA stays in state 0
     forever, so the room never checks the tail. Also BF is still alive in level 0x22 and asks the same.
2. **func_1509DFCC** (game_eu_CA630.c, NON_MATCHING m2c from port P16), case 0x19 / 4: the C loop reads +0x48 of
   `node->next`, not of the node (skips each list's first node and reads NULL+0x48 at the end of the list); the asm
   (`lbu t5,0x48(v0)` before `lw v1,8(v0)`) checks every node. In the room the C answers **1 while the tail is still
   there** (only node skipped; null+0x48 = 231 from the null-zone DL writes of P171) - asm 0. With only (1) fixed the
   room would end without the tail; with a dirty null zone holding 2 at +0x48 it would never end.

No asm stub is involved in the room logic (func_1513FAB4, the scene-start set, func_eu_1501B640 are not on this path).

## 4. The real route after the intro's scene 1 traps (with `?p174fix=1`)

Fixing func_1509CBD8 for every event (evB / evD-evF): BF starts scene 3 of level 0x18 at 10725 (no death, no level
0x22) and the game traps 8 frames later: **RuntimeError: memory access out of bounds at 10733 in func_150623F4**
(game_83300.c, NON_MATCHING) <- func_150619A8 <- func_15018DFC. wasm offset 0xb5ea0 = `load16 (D_800D2104[k] + 6)`.
Probe `[p174ptr]`: at 10733 all active objects get +0x74 == 0xF (first time), and **D_800D2528 and D_800D2104 (EU
0x800D2528 / 0x800D2524) are both NULL**, so `D_800D2528[k]` reads the null zone (non-zero DL garbage) and
`D_800D2104[k]` is a garbage pointer. The asm does the same loads, so on N64 these path tables must be set when scene 3
runs: a producer is missing (no direct `sw` to either symbol in asm/ or src_eu; probably the level path loader).
`?p174fix=2` (level 0x22 only) still breaks: the stale BF event asks the same query in level 0x22 and starts scene 3
(evG: same trap at 18492).

## 5. Ordered blockers

1. **func_1509CBD8** (game_eu_CA060.c): real C from the asm, `s32` return (6 cases, jtbl_8009E828). This is the root of
   the whole "first room" problem: without it the new game takes the death detour, and the death room cannot end.
2. **func_1509DFCC** (game_eu_CA630.c) case 0x19: test +0x48 of the current node before moving to `next`.
   (1) and (2) go together (producer before consumer: with (1) alone the room ends with the tail still there.)
3. After (1): the scene-3 trap at 10733 in **func_150623F4** (game_83300.c): find who sets D_800D2104 / D_800D2528
   (EU 0x800D2524 / 0x800D2528) for level 0x18 scene 3; check func_150623F4's C against the asm while there (m2c
   body, uninitialised sp4C on the `D_800D2528[k] == 0` path).
4. func_1509C850 / func_1509DD0C (D_80088874 entries 0 / 13) are `void` too; their results are not tested by the events
   seen, but check the asm's v0.
5. P171 items unchanged: func_15147F50 / func_15147FA0 record argument (`?p171fix`), func_1515C388 / func_1515C6F4
   (null-zone DL writes: they also feed garbage to the NULL reads above).
