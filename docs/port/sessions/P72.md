# Session P72: the respawn-walk hang found and worked around (branch `port-web`, 2026-10-22)

Worktree `~/conker-wt/web` at c899e0c (P69). Scratch bisect worktree `~/conker-wt/web-bisect` (detached, removed at
the end).

## Result summary

- **Cause: port-b P64's func_150D1D20 (game_eu_FF530.c, view quad) writes through two NULL buffer pointers into
  the null zone.** Its C is correct against the asm (§2). The pointers are NULL only in the port, because the
  allocator of both buffers, func_15000AD0 (game_2DF70.c), is still an asm stub.
  - D_800DC2E0 is the Mtx buffer: guMtxF2L writes 64 bytes at (p * 2 + fb) * 0x40.
  - D_800DC2B8[p][fb] is the vertex block: four t coordinates at +0xA / +0x1A / +0x2A / +0x3A.
  - Both writes land at wasm 0x00..0xFF, the null zone. Other asm stubs return NULL, and the game reads "objects"
    through those pointers in that same zone. A nonzero word left there became the garbage node 0x243C / 0x2450 at
    the head of D_800DD280[1][0]. func_151670C0 → func_15169824 then freed it twice, and func_10003C6C spun on the
    cycled free list.
- **Fix (port side, TEMPORARY):** `port/gfx/p72_checks.c` wraps func_150D1D20. If D_800DC2E0 or
  D_800DC2B8[p][fb] is NULL, the call returns gdl unchanged, which is what the asm stub did. It logs once:
  `[p72] func_150D1D20 frame N: ... NULL (func_15000AD0 is an asm stub): skipped (TEMPORARY)`. Remove the
  workaround when func_15000AD0 is C. No game .c file was changed.
- **Confirmed:**
  - The node reproducer now returns: rc 0, 2416 frames, no `DOUBLE FREE` / `BAD NODE`, `[heap]` 0 errors. With
    `heapwatch=1`: 2410 frames, no errors.
  - P63's walk script (`15000:0:0:80; 22000:0:0:0`, `p61check=20`) reaches the level warp `func_1501C710(1, 0x2C)`
    at frame 1077 and comes back `(1, 0)` at frame 1157. That is the same as P63 (P69 hung here).
  - Real-time Chrome (Metal, `heapwatch=1&p69free=1`, KeyW held 29-37 s): fall, death, respawn (frame 1721), walk
    out of the doorway, warp 0x2C at frame 1793 and back at 1873, then idle to frame 2765. 0 heapwatch breaks,
    no RuntimeError, no double free. Second run: warp at 1781 and back at 1861.
  - `P72_screenshot.png` (Chrome, 37.0 s) shows Conker in the grass field past the doorway, just after the
    0x2C round trip. The 0x2C stay is only ~80 frames, and the dense shots do not show a separate scene for it.

## 2. func_150D1D20 against the asm

`?p72quad=N` logs each call. From frame 1012 on, after the respawn, the game calls it every 4 frames with
`scroll 21.14`, `angle 0`, player 0, fb 0 / 1. Every call logs `D_800DC2E0 00000000` and `D_800DC2B8[p][fb] 00000000`.

The C matches the asm line by line:

- `lw D_800DC2E0` + ((p << 1) + fb) << 6, which is `(Mtx *)D_800DC2E0 + (p * 2 + fb)`.
- `D_800DC2B8 + p * 8 + fb * 4`, which is `Vtx *[][2]`.
- `sh` at 0x0A / 0x1A (top rows) and 0x2A / 0x3A (bottom rows), with values `(top + 0x100) << 5` /
  `(bottom + 0x1FF) << 5` plus `trunc(scroll * 81.0f)`.
- `lw D_800BE628` (a pointer) + p * 0x180, + 0xBC for the view matrix and + 0xB8 (lhu) for the persp normalisation.
- The texture descriptor at sp+0x64 (word, half 4, half 0x100, bytes 0 / 3 / 0).
- The call arguments (func_1501A490, func_150954E4 with stack args 0, 0, 2, 0x100, 0x100, 3; func_1511084C(rot, 0,
  0, angle); func_150A7A48(rot, player + 0xBC, view); guMtxF2L(view, mtx)).

**No bug in the converted C.** Both buffers come from func_15000AD0:

- `jal allocate_memory` → `sw $v0, D_800DC2E0` at 0x15000C70 and 0x150012DC.
- The D_800DC2B8 table is filled at 0x15000B60 and 0x150012E8.
- func_15000AD0 is an asm stub (`[stub 13] func_15000AD0 ... frame=1`).

func_15112074 (asm stub) also reads both buffers.

**For the port branches:** converting func_15000AD0 (game_2DF70.c) removes the need for the TEMPORARY guard. Until
then, any newly converted C that writes through a pointer only a stub sets can corrupt the null zone the same way. A
`?p69free=1` run shows it as a garbage node in an object list.
