## 1. Node noev "stall" after the 40dc311 merge: not a stall
- `noevA` (P131 knobs: PORT_P110NOEV=1 P61CHECK=20 P69FREE=1 HEAPWATCH=1 P78NULL=1 P88SCENE=8, 80 s): death 985,
  0x2C 1385, back to 0 at 1465, heap 0, null 0, traps 0, last logged frame 4389.
- `noevB` (PORT_P110NOEV=1 only, 80 s): "last frame" 1745, as P137's noev2 / noev3. But the end-of-run counters are the
  same as noevA: scheduler 4482 vs 4486 frames, gfx 1120 vs 1121 DLs, audio 2240 vs 2242 tasks; the same stubs are hit
  in the same order at the same frames, incl. the two `[vis] new dl/tree` level switches (0x2C warp and back).
- Cause: P137's `sum.py` "last frame" is the last log line that names a frame. The death / level / sound lines come
  from the `?p61check` wraps; without PORT_P61CHECK the only frame-bearing lines after ~1000 are pad reads, which
  stop when the padscript ends (31 s ~ frame 1740). The game kept running. Chrome had p61check on, hence "clean".
  The `thread 4 blocked (send)` line at the end is in the good run too (state at exit, not a deadlock).
- Fix (tooling): `p140/sum.py` prints "last logged frame" plus a `progress:` line (scheduler frames, gfx DLs). No
  bisect needed; 40dc311 is not implicated.
