## 1. difftest root causes (`tools/port/difftest/difftest.py`)

### a. FPRs were never set or read (big)
Unicorn 2.0.1's `reg_read` / `reg_write` of the MIPS FPRs are **no-ops**: `reg_write(F4)` then `mfc1` reads the old value,
and `reg_read(Fn)` is always 0. So since P1:
- float arguments (f12/f14) were never set,
- stubs never returned a float (f0 after a stubbed call = whatever the caller had in f0),
- f32/f64 return values, FP call arguments and f20–f31 restoration were compared as `0 == 0`.

FPRs now move through memory with real code. k0 (never used by compiled code) = `SCR` (0x807FE000, writes not recorded):
a prologue loads f12–f15 and f20–f31 from SCR, then `jr k1` (= the function); every stub is `j HELPER; nop`, the helper
(at `region | 0x0E000000`) saves f12–f15 and loads the stub's random f0/f1/f2, then `jr ra`; an epilogue at RET_MAGIC
saves f0/f1/f20–f31 and a done marker. FP call arguments are compared per the callee prototype (`proto_fregs`: only leading
float/double params travel in FPRs); with no prototype, only FPRs both sides set right before the call.

### b. The P17 "candidate float literal reads as 0"
A second Unicorn 2.0.1 bug: after an access to **virtual page 0** (null pointer + offset), a kseg0 page in the same softmmu
TLB slot (`(vaddr >> 12) & 0xFF == 0`: 0x80000000, 0x80100000, …, 0x80700000) reads wrong data or segfaults
(micro-test `port_work/p18/uc_alias.py`). The candidate TU's `.rodata` sat at TU_BASE = 0x80700000, so a candidate's own
literal read 0 whenever the function had touched page 0 first (func_151B97C4: a0 = 0 in trial 43). TU_BASE is now
0x80705000, and fake-heap pointers skip index-0 pages (`heap_ptr`).

### c. Definition regex
`find_file` / `func_span` (and selftest's `ext`) matched an indented call line `if ((func_X(...) != 0) && ...) {` as the
definition of func_X (func_15123934 selftest ERROR after P17 inserted func_150F2C20). Definitions must now start at column 0.

## 2. Per-trial wall limit and orphan trials

- `wait_child`: the parent reads a trial's result with `select` and a deadline (`DIFFTEST_TRIAL_WALL`, default
  max(60 s, 2 × DIFFTEST_BUDGET)). On timeout the child is SIGKILLed and the trial counts as inconclusive
  (`[n trials crashed, m hung]`). The child is also killed if anything interrupts the wait (convert.py's SIGALRM `_Hang`).
- `die_with_parent`: each trial child sets `prctl(PR_SET_PDEATHSIG, SIGKILL)` (and exits if the parent is already gone);
  convert.py's per-function child does the same, so killing convert.py or a function process takes its trials with it.
- Test `port_work/p18/test_hang.sh` (container; test knob `DIFFTEST_TEST_HANG=<trial>` makes that trial sleep):
  wall limit 5 s → `EQUIV ... [1 trials crashed, 1 hung]`; SIGKILL of a difftest parent → its trial child is gone 1 s later.

## 3. Table lint (`cfix.table_problems`, `lint:table` in convert.py)

Flags, in a candidate body: an array it defines itself (static / const / initialized) whose values are not the ROM's at
the name's EU address (`symaddr`; `D_X` names are US addresses), that has no initializer, is not named after a ROM address,
whose size runs into the next known symbol, or that is indexed past its size (constant index ≥ n, or any variable index
into a 1-entry array). Plus `width_problems`: `*D_X` / `D_X[0]` read with the declared element type while the asm accesses
`%lo(D_X)` with another width.

Scan of all inserted bodies (`port_work/p18/scan_tables.py`): 2 real bugs, both fixed and EQUIV:
- func_15008BF0 (game_360A0.c): D_80095B48/4C/50 were defined as `u8[4]` and read with `*D_X` → one byte (59.0f instead of
  0.00219f). Now `*(f32 *)D_X` (the header declares them `u8[]`). The old body was EQUIV: the values only reach a stack struct
  passed to a callee, which difftest does not compare (a mutant of the constant is still EQUIV).
- func_15007440 (game_33990.c): checksum compared with `*D_800BE778` (u8), the asm uses `lhu` → `*(u16 *)`.
Known-bad checks: P17's `static f32 D_800A6C60[1]` with a variable index and a wrong-valued table are flagged.
No batch EQUIV in this session was flagged.
