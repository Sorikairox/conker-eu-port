## 1. difftest: the candidate was dropped for NM blocks holding more than one function

`build_tu` replaces the whole `#ifdef NON_MATCHING ... #else #pragma ... #endif` block only when `#endif` follows
the pragma directly. game_eu_48B10.c's block holds func_1501B300 **and** func_1501B640 (both sides), so the
candidate went next to the pragma in the `#else` side, which `nm_resolve` drops: **every func_1501B300 run tested
the src_eu body, not the candidate** (P68's EQUIV results are valid for the src_eu body = the P68 draft; the mutants
could never die). P43 had hit the same effect.

Fix (`tools/port/difftest/difftest.py`): when the NM side of the enclosing block defines the function, only that
definition is replaced; and `build_tu` now raises an error when the candidate body is missing from the resolved TU
(no silent fallback). Other functions with this layout: func_150183D0 / func_150184B0 (game_eu_45B90.c),
func_1507F3B0 / func_1507F834 (game_eu_AC770.c) -- their earlier mutant results were obtained before the blocks were
merged, but any re-test now uses the candidate.

Selftest (`tools/port/difftest/selftest.sh`): `func_1501B300 --self` EQUIV and the mutant
`out[1] = negSinPitch * 127.0f` -> `x * 127.0f` DIFFER (it was EQUIV before the fix). 28/28 ok.

func_1501B300 mutants re-run (`port_work/p73/b300_mut.log`): the rate mutants (0.1 / 1.0 -> 0.03) are now killed
(by random trials). All 15 P68 mutants: 11 killed. Survivors: `(delta <= 0.0f)` (equivalent: |delta| > 90 there),
`pitch <= 0.0f` and the two `360.0f <` boundaries (only differ for exactly 0 / 360; 0 -> 360 -> -0 folds back), UNVERIFIED by test. The D_800BEAE0 / D_800BEAF0 addresses were right (absolute symbols at their names).
