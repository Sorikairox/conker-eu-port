## 1. MP3 ABI commands 7 and 8 (voice clips)

### What the game does (all matched C)

- **Voice clips** are asset `(0x16, id)`. `func_1001263C` loads them with `func_1502B020(&size, 2, 22, id)`
  and starts the stream with `func_151F2960(rom, size)`. They are MPEG-2 Layer III files: header
  `FF F3 30 C0` (24 kbit/s, 22050 Hz, mono), 78-byte frames, one granule (576 samples) per frame.
- **Decoder tables** (`func_151F2960`):
  - asset (0x17,4) holds the Huffman tree index, 36 offsets. `func_151F3DE0` relocates it onto (0x17,6).
  - asset (0x17,5) is the fast table, 0x4400 bytes: `[tbl << 8 | next 8 bits]` = `y << 4 | x`, with the code length at +0x2200.
  - asset (0x17,6) holds the trees, 0xA410 bytes, as 4-byte nodes `{child0, child1, x (-1 = inner), y}`.
  - a 0x8000-byte pow table is allocated.
- **CPU decoder** (`game_221290.c`): Perfect Dark's mp3 library. Its inner loops are hand-written asm:
  - `func_151F9150` bits;
  - `func_151F9184` / `func_151F933C` Huffman;
  - `func_151F94E0` / `func_151FA3E0` IMDCT.

  It writes one granule per channel into `unk2070[6][0x488]`:
  - `+0`: s32 `16 << 16` and its negation (the gain);
  - `+8`: 18 time slots x 32 subband samples, s16, with `value * 2048`.
- **Stream handler `func_151F2E88`** runs once per 184-sample sub-frame. Per decoded granule it emits:
  - `08000000 / state` (MP3ADDY);
  - `07000000 | index / granule buffer` (MP3);
  - `index -= 0x24` (18 slots x 2, mod 0x20);
  - then LOADBUFF of the PCM into MAIN (mono) or 0x4E0/0x650, CLEARBUFF, SETVOL x3, ENVMIXER.

  The state is `D_800E1224`. It is the same word as `&D_800E0D80 + 0x74`, because `D_800E0D80` is
  0x800E11B0 in the EU ROM. The handler zeroes 0x440 bytes there when a stream starts.

  Stereo would read `D_800E1224[1]` = `D_800E1228`, the index, as a second state pointer. That is
  harmless, because voice clips are mono.

### What the RSP does: `port/audio/aud_abi.c`, `mp3_synth`

It is the polyphase synthesis filterbank (ISO 11172-3, 2.4.3.2). For each of the 18 slots:

- matrixing of the 32 subband samples into X[0..31];
- the 64-sample V vector is built from X by symmetry;
- a 16-vector FIFO at position `index/2 - slot`;
- the 512-tap window D;
- the output is `clamp(gain * sum)`, with gain = the header's high halfword (16).

The 576 PCM samples overwrite the granule buffer from its start.

- **Window:** read from the user's ROM. It is the audio ucode data at **0x2CFD0**, next to the
  resample table at 0x2CD80. Row 2j holds D[j + 32i], scaled so that D[256] = 1.144989 is 32767. j > 16
  comes from the prototype's symmetry.
- **State:** the FIFO is kept in float on the PC side, keyed by the MP3ADDY address. A marker word
  in the game's state buffer ties the two together, so the game's bzero at stream start resets it.
- **Licence:** written from the ISO description. rsp-hle is a behavioural reference only, for the
  command fields; see `port/audio/LICENSES.md`.

### Decoder inner loops: `port/audio/mp3_pc.c` (TEMPORARY, BOOT_SRC vbe TU)

- The bit reader and the two Huffman routines are translated from the asm, including the asm's
  private helpers `func_151F9060` / `func_151F911C`.
- The two IMDCTs are written from the standard. The asm was checked for the semantics:
  - frequency inversion happens inside (`andi a1, 1`);
  - arg4 is the window;
  - the output is window * imdct + overlap, and the new overlap is stored to arg3.
- **Remove these when the port branch converts `game_eu_226870.c` / `game_eu_227BF0.c`.** Otherwise
  the link sees two definitions.

### Verification

Test: `VOICETEST=<id>[:calls] port/web/boot.sh 8` → `port/build/audio/voice.wav`; page
`&voicetest=3`. Entry: `port_voice_test` in `aud_test.c`. It drives the real `func_151F2960` and
`func_151F2E88`, then appends INTERLEAVE and SAVEBUFF.

- PC parts:
  - the decoder tables are DMA'd directly;
  - a PC stream DMA callback replaces `func_151F3C4C`, which needs the asm-initialised audio DMA table;
  - the volume, pan and dry/wet are set through the game's own setters;
  - no filter.
- The test stops at state 3, because state 3 would free the tables.

```
VOICETEST=3  -> 207 calls, 202 played, 64 MP3 granules; rms 2476 peak 23023, diff/energy 0.240 -> PASS
VOICETEST=0:2000 -> 1995 played (367080 samples); rms 4077, diff/energy 0.058 -> PASS
```

Speech check on clip 3 (scratch Python, numpy-free):

- the rms envelope shows syllables and pauses: 0 0 6 14 42 59 34 13 3 2 0 0 0 3 … (x100, 23 ms);
- 74% of the energy is below 1.4 kHz, almost none above 5.5 kHz (the 24 kbit/s encoder's low-pass);
- the median spectral centroid is 928 Hz;
- 16 of 52 active frames are voiced (autocorrelation > 0.6 at 80–400 Hz).

White noise would give a flat spectrum and a diff/energy of about 2.

Clipping: only 2 of 367080 samples are near the peak (p99 = 14707), so the gain is right. The equal
peaks (~23023) are the envmixer's 0.707 centre-pan gain on a rare full-scale sample.

Not verified against an independent decoder: there is no ffmpeg/numpy on the host, and no host
installs are allowed. There is no A/B test of the frequency-inversion convention either. A stereo
stream would hit the `D_800E1224[1]` quirk.

## 2. Renderer

### Conker lighting (`port/gfx/gfx_f3dex2.c`, `light_vtx`)

- `G_MOVEMEM 0x0E` sets the normal-array base for the following `G_VTX`.
- For vertex slot k (the index in the 32-entry vertex buffer), x and y are s8 at `base + 2k`, and z
  is the low byte of the Vtx flag (+7).
- This was checked on the ROM model `0xBA0708`:
  - the normal chunks are 0x40 bytes (32 slots x 2) per batch, and they advance together with the vertex batches;
  - a flat panel at x = 1 has normals (127, 0, flag 0), i.e. +X.
- The colour is `vertex rgb * min(1, ambient + Σ max(0, n·dir_l) col_l)`, with n rotated by the
  modelview and normalised.
- Lights use the F3DEX2 Light layout, read at Rare's 48-byte stride:
  - `G_MOVEMEM 0x0A`, light n at offset (n + 2) * 48;
  - `G_MOVEWORD 2` = n * 48;
  - the point-light fields are not interpreted.
- The 48-byte stride and the multiply-by-vertex-colour come from what is known about this ucode
  family. They are **not checked against the RSP code**. Without light commands the ambient is 1,
  which gives the old look.

### Per-bone matrices (`port/gfx/gfx_demo.c`, `load_bones`)

- Skinned model files have a header with the bone table offset at +0x10 and its size at +0x14.
- A bone entry is 16 bytes: `{u8 parent (FF = root), u8 index, u8 index, 0, f32 x, y, z}`, the offset of the joint from its parent.
- Bone matrix i (segment 3 + 64 i) = translate(sum of offsets up the chain) x model matrix.
- The viewer's bounds are now measured after the modelview with an identity model matrix, so the
  framing includes the skeleton.
- Bone counts of the four skinned viewer models: 9, 2, 28 and 28.

## 3. Real browser audio check: found and fixed a dead audio path

- **`port/web/audprobe.sh "app=game&audonly=1&audtest=26390" [secs]`** works as follows:
  - it serves the build read-only;
  - it starts headless Chrome with `--autoplay-policy=no-user-gesture-required` and drives it over
    the DevTools protocol (`port/web/audprobe.js`, the host node 24's global WebSocket, no packages);
  - it polls the page's `window.audprobe` once a second. `main.js` `installAudioProbe`
    (`&audprobe=1`) wraps every ScriptProcessorNode's `onaudioprocess` and counts the callbacks, the
    frames pulled and the non-zero samples.
- **Bug found:** the P11 SDL2 build never created an AudioContext. `SDL_OpenAudio` "succeeded"
  with 0 Hz / 0 channels: the SDL2 port in the image has no Emscripten audio driver linked, so SDL
  used a dummy device. **No browser audio was ever played.**
- **Fix:** `aud_out.c` now uses a direct Web Audio sink, a ScriptProcessorNode that reads the ring
  from the wasm heap and advances the read index. It needs no wasm call in the callback, so it is
  safe with ASYNCIFY. The first click or key resumes it.
  - It is an `EM_JS` named **`__port_…`**: `gen_stubs.py` turns any other undefined name into a
    "missing" C stub, which silently replaced the first version.
- **`&audonly=1`** loads the data segments (`_port_audio_prepare` → `port_mem_load`) without starting
  the game threads.
- **The game page blocks its main thread in real-time headless Chrome.** DevTools evaluate and pause
  get no answer within 90 s, with or without audio, and with `&timer=1` too. The demo page is fine.
  It only works under `--virtual-time-budget`. This is not investigated yet.

               stereo frames), rms 0.1265 -> [audprobe] PASS
