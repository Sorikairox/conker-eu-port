## 1. Input: keyboard + Gamepad API → PIF → the game's controller read

**PIF model moved to `port/ultra/pc_pif.c`** (from `pc_os.c`), with the controllers and the EEPROM.
`pc_os.c __port_io_write` calls `port_pif_dma()` for SI_PIF_ADDR_WR64B/RD64B, as before.

- The PC `osContStartReadData` packs libultra's controller-read block (per channel `FF 01 04 01` + 4 reply
  bytes, then `FE`, `pif_ram[63] = 1`) and runs it through the same `pif_run()` the game's raw SI code
  uses. It copies the replies into `cont_ram` (libultra's `__osContPifRam`), then posts the SI message.
- `osContGetReadData` unpacks `cont_ram` like `__osContGetReadData`: errno = `(rx & 0xC0) >> 4`, button,
  stick_x, stick_y. Absent pads report `CONT_NO_RESPONSE_ERROR` from the PIF itself (rx | 0x80).
- **Bug found and fixed on the way:** the first version unpacked `pif_ram` directly. Any other SI user
  between the two calls (the game's pak writes, the EEPROM) overwrote it, and the game read garbage
  buttons. Hence the separate `cont_ram`, which is what libultra does too.
- `osContInit` reports the present pads from the page's pad state.
- **Page → wasm without calls:** `port_pad_state()` returns `int32 port_pads[4][4]` =
  {present, N64 buttons, stick_x, stick_y}. `main.js` writes it from `requestAnimationFrame` via
  `HEAP32`, so no wasm call happens from input callbacks (same rule as the audio ring).

**Mapping (`main.js`):**
- N64 bits from `PR/os_cont.h` (A 8000, B 4000, Z 2000, Start 1000, D-pad 0800/0400/0200/0100,
  L 0020, R 0010, C 0008/0004/0002/0001).
- Stick: 80 on the axes and (70, 70) at the corners of the octagonal gate (`octagon()`); a half-tilt key
  halves it. Gamepad left stick has a 0.15 radial dead zone, rescaled, y up-positive.
- Default keys: WASD stick, Space A, F B, Q Z, R L, E R, Enter Start, IJKL C-buttons, arrows D-pad,
  Left Ctrl half tilt.
- Standard Gamepad: A→A, X→B, B→C-down, Y→C-left, LT→Z, LB→L, RB→R, Start→Start, d-pad→D-pad,
  right stick→C-buttons (threshold 0.5), left stick→stick.
- Pad 0 = keyboard merged with the first gamepad; gamepads 2-4 = pads 1-3.
- **Remap panel** (Controls): click a cell, press a key or a pad button (Esc clears a key). Stored in
  localStorage (`keys`, `padbuttons`) as differences from the defaults; "Defaults" resets.
- Bound keys don't scroll the page while the game runs. Alt+F or F11 toggles fullscreen.

## 2. Saves: EEPROM in IndexedDB

- `eeprom[2048]` (16 Kbit) lives in `pc_pif.c`. Exports: `port_eeprom_ptr`, `port_eeprom_size`.
- PIF command 0x05 that **changes** a block calls `Module.portEepDirty` (EM_JS `__port_eep_dirty`).
  `main.js` debounces it (400 ms) and stores the 2048 bytes in IndexedDB.
  - The database is `conker-port` v2, with stores `rom` and `saves`.
  - The key is `<ROM sha1>/eeprom/<slot>`. The slot is `?slot=N`, default 0.
- At boot, the save is copied into `eeprom[]` after `port_set_rom` and before `callMain`.
  - If IndexedDB does not answer in 3 s, the boot goes on with a blank EEPROM and **saving is turned
    off** for the session, so a stalled read can never overwrite a real save with a blank one.
  - Headless `--virtual-time-budget` stalls IndexedDB; `shot.sh` gfxdemo hung on it before this guard.
- **Export / Import .eep** (Saves panel): 2048 raw bytes (a 512-byte 4K image is zero-padded).
  - An import goes to IndexedDB. A running game reloads to read it at boot. Dropping an `.eep` file on the
    page imports it too.
- **Test (write → reload → read, real Chrome, one profile; PROBE_LOG of the page console):**
  ```
  [eep] no save for ee7bc66…/eeprom/9: blank EEPROM
  [eeptest] wrote blocks 38-3F (seed 4242), 8 EEPROM writes so far
  [eep] saved 2048 bytes to IndexedDB (ee7bc66…/eeprom/9), 8 block writes      <- one debounced put
  -- loading conker.js                                                          <- page navigated
  [eep] loaded 2048 bytes from IndexedDB (ee7bc66…/eeprom/9)
  [eeptest] PASS: read blocks 38-3F back (seed 4242), 0 of 8 differ
  -- loading conker.js                                                          <- slot 8: control
  [eep] no save for ee7bc66…/eeprom/8: blank EEPROM
  [eeptest] FAIL: read blocks 38-3F back (seed 4242), 8 of 8 differ             <- expected
  ```
  Command:
  `PROBE_NOAUDIO=1 PROBE_STEPS="10000:nav:app=game&eeptest=r:4242&slot=9; 20000:nav:app=game&eeptest=r:4242&slot=8" port/web/audprobe.sh "app=game&eeptest=w:4242&slot=9" 30`.
  - `&eeptest=w:SEED` / `r:SEED` call `port_eep_test`. It writes and reads blocks 0x38-0x3F with the
    exact PIF blocks libultra's `__osPackEepWriteData` / `__osPackEepReadData` build, on channel 4.
  - The game's own save path, `osEepromLongWrite` `func_151DD4A0` (pumped by `func_151DD588`), runs
    only from its save menus, which are not reached yet. In 10 s the game issues no EEPROM command.
  - Node: `EEPTEST=77 port/web/boot.sh 10` gives `[eeptest] PASS` (no IndexedDB in node).

## 3. Page UX (`port/web/index.html`, `main.js`)

- **ROM drop zone** over the screen. It takes drag and drop anywhere on the page, or the picker.
  - It says clearly that the ROM never leaves the browser and is kept only in IndexedDB.
  - The SHA-1 check shows in the status line (green "Conker EU, SHA-1 ok" or red with the hash).
  - Start is enabled only for the EU ROM. The cached ROM is reloaded on the next visit.
- **Screen:** a 4:3 box sized to the window, `min(100%, (100vh - 140px) * 4/3)`. Fullscreen (button,
  Alt+F, F11, double-click) keeps the aspect, with black bars.
- **Pause:**
  - Pause/Resume button, and Esc outside fullscreen.
  - **Automatic on tab hide** (`visibilitychange`). `?nohidepause=1` disables it.
  - `port_set_paused()` (pc_os.c) skips main-loop frames, **stops the game clock** so timers don't
    fire all at once on resume, and suspends the AudioContext.
  - Tested in Chrome: 36 frames at hide, still 36 three seconds later, 115 after showing it again.
- **Volume:** the slider drives a GainNode that `aud_out.c` now puts between the ScriptProcessor and
  the destination. It is stored in localStorage.
- **Debug console behind a toggle:**
  - It holds the log, "Scheduler demo" and "Dump threads". It is hidden by default; `?debug=1` opens it,
    and the last state is remembered.
  - The log keeps its last 5000 lines. The probes read `#console` while it is hidden.
- **Dev flags unchanged:** `app`, `romurl`, `audonly`, `audtest`, `voicetest`, `audprobe`, `dump`, and
  every C `port_flag` (`det`, `gfxdemo`, `dltrace`, …).
  - Checked: `shot.sh … 'app=game&gfxdemo=1' 6000` renders the viewer.
  - Checked: the audio, input and save runs above use `app=game`.

## 4. Audio resume on the first gesture

- `aud_out.c` no longer installs its own click/key listeners. After creating the context it calls
  `resume()` (allowed after a gesture, sticky activation) and `globalThis.portAudioReady(ctx)`.
- `main.js onGesture` (pointerdown / keydown / touchend, capture) resumes a suspended context unless
  the game is paused. A small "click or press a key to enable sound" hint shows while the context is
  suspended.
- **audprobe, default autoplay policy** (`PROBE_NOAUTOPLAY=1`, a CDP mouse click at 6 s):
  ```
  t=2s..5s  ctx 1, state "suspended", 0 callbacks
  step t=6.0s click
  t=6s      state "running", 6 callbacks, 24564 non-zero
  t=12s     143360 frames pulled, 203864 non-zero samples
  [audio] context created: suspended
  [audio] context resumed by user gesture: running
  [audprobe] PASS: Web Audio pulled 143360 frames, 203864 non-zero samples
  ```
  Command:
  `PROBE_NOAUTOPLAY=1 PROBE_STEPS="6000:click" port/web/audprobe.sh "app=game&audonly=1&audtest=26390" 12`.
  The 203864 non-zero samples are the same count as P14.
