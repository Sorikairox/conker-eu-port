## VM design (func_150ADFD0)

- **Hand-written assembly, not compiled C**: the .s is marked "Handwritten function"; it saves gp / fp, stores its sp
  in D_800D3858, uses `add` / `sub` / `neg` pseudo-ops and `srlv` with constant shift registers, and dispatches
  through 5 jump tables (entry, 3 operand decoders, opcodes). Per the asm2c policy it got a readable C interpreter
  (no asm2c_hand), in game_eu_DB7E0.c (not nm_asm).
- Machine: u16 opcode word (bits 0-5 op, bit 6 "first immediate is 32-bit", 3-bit modes for up to three operands at
  13 / 10 / 7), D_800876F8 = operand count + 1. Modes: 0 frame slot, 1 variable, 2 data address (value = offset),
  3/4/6 immediate (4 = code offset, 6 = native index), 5 result register D_800D3C68. Operand stack D_800D3C80 from
  +0x17FC down; script call pushes the return pc, `enter n` pushes the frame pointer, `return` ends the run when the
  stack is empty again. Native calls: `D_80088A44[i](sp, 6, operand address)`, args not popped (as in the asm).
- Opcodes: 1-5 add/sub/mul/div/mod, 6 neg, 7 lognot, 8 not, 9-B and/or/xor, C sll, D sra, E move, F jump,
  10/11 jz/jnz, 12-17 lt/gt/le/ge/eq/ne, 18 push, 19 call, 1A return value, 1B enter, 1C return, 1D/1E array load/store.
- **Abort**: func_150AE760's first 6 instructions reload sp from D_800D3858 and jump into the VM epilogue. Its only
  caller, func_1509FD30 (game-state handler, D_80088874[4]), does `func_150AE760(); return 0;` - tail position. So a
  flag is equivalent: func_150AE760 stores EV_ABORTED (-1) in D_800D3858 (nothing else reads that word; the TU
  cannot own .bss in the NM link - a `static` failed with "discarded section .bss"), and the VM checks it right
  after every native call, clears it to 0 like the asm, and returns before storing the result. setjmp/longjmp is not
  available in the N64 NM build. Divergence only where N64 breaks itself (abort after a nested VM run returned).
- Quirks kept: operand 1 in mode 5 reads 6 (t2 holds a shift count), operand 3 in mode 2 reads 5 (t4); VR4300
  div/mod results for x/0 and INT_MIN/-1; add/sub/neg wrap (the asm traps). Not reproduced (VM stops): mode 7
  (jumps into the next decoder or to 0), opcode 0 / >= 0x1F, entry > 4. ROM scan (`p106/evasset.py`, 273 blocks,
  linear walk) shows mode 7 only where the walk hits data.
- The natives 3..12 are code inside the asm VM; in C they are separate functions named by their addresses
  (func_150AE5D8 ...), so the port's table relocation can map D_80088A44's words to them **(web: check that
  n64mem.py treats these 10 addresses as function starts)**.
- LogoScreen (0xC9): entry 0 = enter/return; entry 1 = push 1, push 0x1001, native 6 -> D_80088874 nibble 1 =
  func_1509C850(1, 1, args) (C already).

## Harness changes (tools/port/difftest)

- `DIFFTEST_ROMDATA=1`: every trial loads the ROM .data (jump / opcode tables are .data; even trials had random
  tables). Pokes into ROM .data do not hold then.
- `DIFFTEST_MEMSTK=ADDR,..`: memory words holding a stack address (D_800D3858 = saved sp) compare by class.
- `DIFFTEST_SIGNORE=7`: leave s-registers out of the restoration check (VM natives save ra in s7; the VM saved s7).
- difftest.sh now forwards DIFFTEST_REFLEN (it never did: REFLEN only worked inside the container); empty
  REFLEN = default. Note `--self` ignores REFLEN (reference = candidate length): use a candidate file.
- No selftest case added (new opt-in knobs, no behaviour change by default); selftest result below.
- Harness limits seen: VM-level setups cannot use natives 3..12 (the asm runs them inline, the C calls them; a stub
  at 0x150AE5D8.. also lands inside the candidate's code) and real blocks that call them (rom11/2A/64/CA/D0/120
  DIFFER/fault in cand for that reason); the lw in a jal delay slot (func_150AE674) reads garbage in Unicorn -> model
  check; `--self` with a prototype of a TU function in the same NM block CERRs (func_1509B5AC: use a candidate file).
