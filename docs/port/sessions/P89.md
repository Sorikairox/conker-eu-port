## Harness fix (task 0): stack-range values

`same_val` / `Run.norm` treated every value in the harness stack range 0x80600000..0x8067FFFF as the same 'STK' value, so a
stub-returned or poked pointer there (P86: func_1502AB94 setups returned objects at 0x806xxxxx) hid wrong-offset mutants.
Now only addresses in the part of the stack the function used compare as 'STK': `[min(lowest sp seen, SP_ENTRY - 0x1000),
STK_TOP)`. The lowest sp is read in the first 4 blocks of the function (the prologue block) and at every call. Values
below (stub returns, pokes, random words, such as 0x8066xxxx) compare exactly. `DIFFTEST_STK_OLD=1` restores the old rule
(forwarded by difftest.sh). Selftest: new `chkce` (env setups) and the case file `cases/func_1502AB94.c` (P86 draft):
the P86 setup with the object returned at **0x80660000**: as is EQUIV, the `obj + 0x14 -> 0x10` mutant **DIFFER**s
(`stack arg sp+0x1C ref=0x80660014 cand=0x80660010`), and the same mutant with `DIFFTEST_STK_OLD=1` is EQUIV (the old hole,
kept as a control). Stub returns themselves were already heap pointers (`rand_arg`); the hole came from user setups.
