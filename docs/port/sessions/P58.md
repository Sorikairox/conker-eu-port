## 3. func_150A86B0 at runtime (P51's UNVERIFIED items)

Wrap of func_150A86B0: object, state, joint count, remap slots and their table entries, the adjustment scan (done
the evaluator's way), the asm stubs reached inside, and a check of the n joint matrices written: finite, row norms
and orthogonality of the 3x3 with the root matrix undone, and each joint's distance to its parent against the
skeleton offset times the parent's scale. `?p58dump=K` prints evaluation K of record 0 in full.

**Root matrix (before the func_150A9B0C fix):** `root 0 3.57331e-43 -nan | 1.71129 0 0 | 0 2.1445 0 | 27 21.5 27`
(only the translation row comes from the C func_1502E228). After the fix: `-0.4976 0 0.0490 | 0 0.5 0 | -0.0490 0
-0.4976 | 27 21.5 27` (Conker's 0.5 scale, a yaw).

**Sine table (before pc_tables.c):** with a valid root, every joint's world 3x3 was 0 and all 28 translations were the
root joint's (`e00..e27 ... | 0 0 0 | 0 0 0 | 0 0 0 | 26.986 28.316 26.858`). `D_150AA11C` was in
`port/stubs/data_stubs.c` as `unsigned char[0x100]`, weak, zero: too short (the table is 513 floats) and empty.

**Endianness:** after the fixes the matrices pass every check (`50/50 evaluations: 0 non-finite, row norms
1.0000..1.0000, max |cos| 0.00000, bone lengths 27/27`). With `p58anim` (§4):
- the header in the state equals the ROM bytes (`FA1D041EF927A704...` at ROM 0xC167F8);
- `+0x30` data after func_1502DB14 equals the ROM stream at 0xC168B0 (`B3347039CE000015...`), next key frame
  `A73470794E081075...`;
- the pose changes smoothly with the frame time and loops (anim 5, 30 frames: max joint change per frame 5.4-19°,
  frame 29 -> 0: 5.6°; anim 0, 45 frames, key step 4: 12-40°, wrap 17.9°); a wrong byte order would give garbage
  angles with random jumps.
So the BE byte reads of header / stream and the typed loads of the skeleton floats and the sine table are right
under vbe (vbe byte accesses see N64 byte order; the DMA is a bswap32 copy).

**Callback table:**
```
[p58] jtbl_8008891C_game[1] = {0000125A, 1} -> func_15036FD8
[p58] jtbl_8008891C_game[2] = {0000125B, 1} -> func_15037224
[p58] jtbl_8008891C_game[3] = {00000D73, 1} -> func_1503A8FC
```

All five words are in `port_reloc` (n64mem.py rule (a): exact function starts) and point at the right functions.
The callbacks take no arguments (they read D_800CC2D0[D_800C3E78] / the arena), so the `v:` call sites match.
Conker: `remap slot7->1 slot12->1`, `stubs inside: func_15036FD8 x2`.

**Adjustment buffer (func_150342D0 stub), `?p58noterm=1`:** `adjust scan 214 (angle 143, scale 71, max off 780)`
on the first call, then 310 (≈196 angle / 114 scale edits, offsets up to 0x7F7) every call: harmful (garbage added to
the angles and multiplied into the scales). The scan ends on a 0x1000 found in stale stack data, so it is not long.
With the TEMPORARY terminator: `adjust scan 0`.
