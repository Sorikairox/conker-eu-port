## Guard (`tools/port/portguard.py`, `tools/port/portguard.sh`)

Every script in tools/port loads it first: insert_nm.py, convert.py, cfix.py, nmrepair.py/.sh, protocheck.py, progress_nm.py,
nm_layout.py, difftest.sh, difftest/difftest.py, difftest/selftest.sh, rerun_p5.sh. On the host it exits 3 unless:

1. `CONKER_ROOT` is set (port tools have **no** `~/conker` default),
2. the checkout that holds the script is `CONKER_ROOT`, and
3. the git toplevel of the cwd (when the cwd is inside a repo) is `CONKER_ROOT`.

Inside a container (`/.dockerenv`) it does nothing. Tested: with CONKER_ROOT unset, all 12 entry points exit 3. With the port env
and the cwd in ~/conker, all exit 3 ("cwd repo"). With CONKER_ROOT=~/conker, they exit 3 ("script checkout"). With the right env,
protocheck and selftest run normally.

## difftest changes

- **Trailing padding** (`strip_pad`): IDO pads the candidate with `nop`s to an alignment boundary. A candidate that covered the
  next function's first word got no stub there, so a tail call into it ran the padding. The visible symptom was that a *matched*
  function failed its own `--self` check (`func_10004DB0`: "fault only in cand at 0"). Trailing zero words are now dropped
  (one is kept as the delay slot of a final jump).
- **Arity:** with a known prototype, only the **reference's** call-site writes widen the compared argument count. For
  libultra callees (`os*`, `__os*`, `gu*`, `bzero`, `bcopy`), the prototype is exact. Before this, an IDO spill reload into a3
  right before `osSetIntMask` made a2/a3 count as arguments.
- **`DIFFTEST_OUTPARAMS=1` / `--outparams` (opt-in):** each stub writes a deterministic random word (keyed by callee, call
  number and arg index) through every aligned aN that points into the caller's frame. This covers `osRecvMesg(&msg)` and DMA
  buffers, so the code behind out-params now runs. It closes the P5 gap. It is opt-in so that convert.py runs stay comparable;
  consider making it the default after a selftest pass.
- `DIFFTEST_STEP=1` / `--step` (opt-in): a code hook over the body, which makes Unicorn translate one instruction at a time. It did
  **not** cure the `func_100049E0` jump-table problem.
- The `ra` of each call is recorded (debugging).

**Open emulator issue:** with the `switch` version of `func_100049E0` (`port_work/p7/func_100049E0_switch.c`), the candidate's
`lw t7, jtbl(at)` returned 0 after a case-2 iteration. The jump-table memory read back correctly from Python at that moment,
and no write had touched it. The issue is reproducible and deterministic (seed 1, trial 1, call #127). Long runs of this
function also crash the container's Python with a segfault (exit 139) at random, with both Unicorn versions. Treat long-loop
functions' difftest results with care. Debug scripts: `port_work/p7/dbg*.py`.
