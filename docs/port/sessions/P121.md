## 4. The frame-1985 trap (P116: `table index is out of bounds` in func_15169EF8)

Not reproduced in 6 node runs (all passed 1985). Cause found by reading: frame 1985 is track 13's `5/0x5C b4 0` (camera
fade) -> handler A -> **func_1510AEB0** (game_eu_1386C0.c, P15 m2c NM body) on level 0x21. It fills 20 separate stack
locals (sp24..sp5D) and passes `&sp24` to func_15169ED8, which bcopies 0x3C bytes from it into a new effect record. On
N64 the locals form one stack struct; in clang they are separate (and the stores are dead), so the record gets
whatever follows sp24 on the wasm stack. Record +0x40 (= source +0x30, sp54 = 0xA) indexes D_8008CDC0 in
func_15169EF8 -> garbage index -> the timing-dependent trap. Fix for a conversion slot: one struct (S59A0 in
game_eu_1231B0.c is the same layout). Pattern for a scanner: `&spXX` passed to a call while other `spYY` locals are
only stored.
