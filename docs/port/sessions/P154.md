## 3. Gameplay (Chrome, real time, `?padf` frame scripts)

First playable room: a dark round room with a stone pillar, a gargoyle on it and a squirrel tail (extra life) hanging
below it (P154_3). Findings:
- **Movement works.** Stick right / down / left / up (padwalk.py from 18600) moves Conker at up to ~9 units / retrace.
  The camera follows behind him and turns around the pillar (P154_4..P154_8). Positions are finite; max |pos| is 472.
- **Collision works.** The room is a circle with radius ~465-472. Pushing into its edge stops him (x 462 / 454 hold for
  hundreds of retraces while the stick is held). Walking toward the pillar stops at x ~28. Floor y is 0 everywhere.
- **Jump (A) works**: y 0 -> 51 (tap), y 160-216 with A held + stick (hover / long jump), lands back at 0.
- **Pick-up works**: the jump at 18802 (padtongue.py) collects the hanging tail. There is a starburst, the tail and
  its holder disappear and the HUD shows the "3" lives counter (P154_9). Red eyes then move in the dark (P154_11).
- **B does nothing visible**: every B press calls the asm stub **func_15064668** (game_eu_90F50, 445 instructions).
  func_1506045C (C, game_83300) calls it when pad bit 0x4000 or unk31C->pad79[2] is set, so it is the B / context
  action (frying pan, B-pads). On N64 the next room event in this room is probably a B or context action. This is the
  first gameplay blocker.
- **START opens the pause menu** (P154_12, func_151EE0C4 stub x126 per window while paused). The "PAUSED" / option
  text looks noisy and interlaced. It may be the menu's own effect or a texture / combiner (noise dither) problem for
  the gfx slot; not compared with real hardware.
- Animation: walk / run / hover / sit poses are visible; the morph func_1517B270 runs 62 / window. While walking,
  func_15064F50 (asm stub, game_eu_90F50, 946 instructions) is called 8-47 times per window. It sits in the movement
  path of game_eu_78230 (arg0->unk80 / anim choice), and the stub returns 0, so that branch is always skipped.
- Sound: audio runs (audprobe rms 0.07, peak 1.0, non-zero samples). The positional sound-effect emitters
  func_10010154 / func_1000F568 / func_10010344 (init_EB00) are asm stubs and are called every window during play,
  so footsteps / sound effects in the room are missing.
- Rendering: a long dark streak runs from Conker toward the camera, and some floor patches look hatched (P154_10,
  P154_5). These are probably the shadow / decal path; not investigated.
- Heap 0 errors, traps 0, null zone only the known null+0x14 (stub func_1514CFF0 at 4559, seen at 10721).

Stopping point: **gameplay is reached and runs (no hang, no trap)**. Progress past the first room is not shown; it
needs the room's puzzle solved with input. The likely blocker is the B / context action stub func_15064668. I did
not run node --prof because there is no hang.
