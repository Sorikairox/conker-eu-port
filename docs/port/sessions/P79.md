## Method

1. **C side:** clang IR of the browser build, `port/build/ll/*.c.ll` and `port__*.ll`. This is the -O0 IR *before*
   sigs.py, so a K&R call shows what the C passes. For each defined function the tool takes the parameter count and
   the call sites in source order. An indirect call's pointer is traced back through load / store / gep to its global
   (`D_80082ECC`), or `?` for struct fields.
2. **asm side:** `conker/build/conker.eu.elf` (== ROM). The container's `mips-linux-gnu-objdump` produces `-d`, `-t`
   and the data sections (`-s`), cached in `port/build/arity/eu_elf.{dis,sym,data}`. The tool runs a forward
   may-dataflow per function over a0..a3, f12/f14 and the outgoing stack slots:
   - E = entry value, W = written since the last call, X = clobbered by a call.
   - At a call, after its delay slot, slot i is *provided* if it is W, or if it is E and i < the caller's own arity.
   - Stack slots count only after a0..a3, and only if they are never loaded back (otherwise they are locals).
   - f12/f14 are not counted at calls, because IDO uses them as FP temps.
   - Function live-in arity = the highest arg reg / stack arg read while still E, plus a fixpoint for pass-through
     wrappers (func_15084000 hands a0..a3 to func_1505EEF4 unchanged).
3. **Matching:** the k-th C call to f is matched with the k-th `jal f`, and the k-th C icall with the k-th `jalr`
   (`match=loose` when the counts differ).
4. **Tables:** the words of a table symbol, up to the next data symbol, that are function starts. They give the
   targets of an icall and their max live-in (`callee_asm_in`).
5. **Rank:** severity > 0 first, then tier, then kind (D1, I, D3, D2), then severity:
   - tier 3: caller / callee / target named in the p75 / p78 boot logs;
   - tier 2: caller reachable from those or from `port__game_*` through direct edges, and the callee is C;
   - tier 1: one of the two.

   The logs only list stubs and named traces, not C calls, so tiers are coarse.

## Caveats (check the asm before every fix)

- **May-analysis:** a W on any path counts. Examples: an a-reg written for a later use, a loop back edge,
  func_1507C170's `move a1,a3` at entry. E only means the caller's value is still in the register, not that the C
  meant to pass it.
- **`?` icalls** (struct-field pointers: func_1507C170, func_151674F8) and **bss tables** (D_800DBEF4, D_8008A420:
  no data words in the ELF) have no known targets, so severity = asm_n - passed. The `stk:N` counts on
  func_15114708 / func_1517485C are probably locals that are written through another base register.
- **func_150184B0** (D3, live-in 18) is hand-written code that uses its caller's frame. Ignore it.
- **byval structs** count as 1 in the IR. D3 skips callees with byval / double / i64 parameters, but D1 keeps them
  (func_15049350 is a real mismatch).
