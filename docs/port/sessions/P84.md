## 3. Two new runtime blockers exposed by the merge (TEMPORARY port-side measures)

1. **The language byte is 0xFF, so the text bank load reads out of ROM.**
   - Chain:
     - The save-settings checksum fails (game_33990.c), and the game fills D_800E1010..+0x1C with 0xFF.
     - **func_151DDF6C** (game_eu_20B730.c, GLOBAL_ASM, the settings clamp to [D_80090210, D_8009022C] with default D_800901F4) is an asm stub, so nothing clamps the values.
     - The language D_800E101A therefore stays 0xFF.
     - P68's C func_151E7110 (text bank loader) then runs every frame. The u8/s8 compare 255 != -1 never settles.
     - Each run does `[pi] DMA 0x07B9E9C0 out of ROM` (JS stack: func_151E7110 <- func_151E5928) and gets a zeroed bank. Its string scans go through the null zone at about 400 ms per frame, and memory leaks every frame.
   - Measure: a TEMPORARY PC func_151DDF6C, a 1:1 copy of the 30-instruction asm, in `port/boot/pc_overrides.c`.
   - Result: language 0, the bank loads ("OFF.ON..GOAL..COLLECTION..BATTLE") and there are no slow frames.
2. **func_1501E364 never ends at the level 0 load (hang).**
   - V8 `--prof` tick profile (`port_work/p84/prof/`): 100 % of the time is in func_1501E364 -> func_1502457C / func_1501E888 / func_1501ECA4 / func_15020F6C.
   - Cause:
     - P73's scene loader func_1501D348 is now C. It starts the scene: D_800C35EA[0] = 1, counter D_800C39D0[0] = 0.
     - The scene length D_eu_800C3A60[0] is written by **func_1501CE34** (game_eu_4A070.c, 140 instructions, asm stub), so it stays 0.
     - func_1501E364 loops while state == 1 and counter >= length, which is always true.
   - Measure: a TEMPORARY wrap `__wrap_func_1501E364` (port/gfx/p84_checks.c) skips the call while the length is 0 (`[p84] guard` lines). `?p84noguard=1` turns it off.
   - Result: node runs to frame 2177 with heap 0 errors and null zone 0 dirty.
