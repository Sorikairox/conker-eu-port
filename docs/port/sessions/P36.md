## 1. Rare's inflater (init_eu_5DA0, hand asm 0x1000654C-0x100074B8)

It is Mark Adler's gzip `inflate.c` (huft tables, 4-byte entries {e, b, v}) written in asm with the state in registers:
$s7 input, $gp bit buffer, $fp bit count, $f16 output base, $f17 output count, $f18 output limit, $f19 next free table
entry, $s6 table base. The helpers share func_1000654C's 0xA88-byte frame (c[17] at sp+0, u[16] +0x44, v[288] +0x84,
x[17] +0x504, code lengths ll[316] +0x548, tl / td / bl / bd +0xA38..0xA40).

`s32 func_1000654C(s32 src, s32 dst, u32 work)` (called through func_10006530(src, dst, D_8003809C)):
- The stream starts at src + 2 when the first BE halfword is 0x1172, else src + 4 (after the BE u32 size).
- Output limit = 0x70000000, lowered to src - dst when src > dst and to work - dst when that is >= 0 and smaller.
  Copies and stored blocks fail unless count + n < limit (**strict**: the work area must start at least 1 byte past
  the end of the output). Literals are not bounds-checked.
- Dynamic / fixed tables are built **in the work area** (third argument); fixed tables come from func_1000738C
  (D_8003C230: literal table at [1], distance table at [0x272] = D_8003CBF8), built once at boot.
- Returns the output length, 0 on an error.
- Quirks kept from the asm: no `n = x[g]` and no over-subscription check in huft_build; the first huft_build of a
  dynamic block is unchecked; **a fixed block never fails** (inflate_codes' error is dropped, the next block is
  parsed); huft_build returns `y != 0 && g != 1`. For incomplete codes huft_build reads **stale v[] entries** of the
  shared frame, so the C keeps one frame struct (`InfFrame`) with the asm's layout, allocated in func_1000654C.

C: `conker/src_eu/init_eu_5DA0.c` (one block under func_1000654C; the other eight functions have `#ifdef
NON_MATCHING` stubs pointing to it). State struct `InfState`, table entry `InfHuft {u8 e, b; u16 v}`.

Test: **`tools/port/difftest/nmasm_inflate.py`** (new). Both sides run in Unicorn MIPS32 (reference = build/conker.eu.elf
.init words; the 8 `sd $zero` that clear c[] are patched into a jump to a trampoline of `sw`). Real packed assets:
`tools/port/difftest/scan_assets.py` finds **5869** {BE u32 size, raw deflate} records in the EU ROM (sizes 16 B ..
220 KB; first block dynamic 4900, fixed 965, stored 4); each trial picks one (half spread over the size range, half
random, plus all stored-first and the 8 largest multi-block assets). Per trial: random RAM pattern, func_1000738C,
then func_1000654C; compared v0 and all RDRAM except the stack; the reference output is also checked against Python
zlib and the header size. Modes: normal (work 1 byte .. 192 KB past the output), 0x1172 header, output limit too
small (error path: v0 = 0, partial output, partial tables), src above dst, corrupted streams (1-4 flipped bits).
**Seed 2: 1012 trials, 1009 EQUIV + 3 skipped (both time out / fault on corrupted data), 4.38 MB inflated;
seed 7: 1012 trials, 1008 EQUIV + 4 skipped, 4.02 MB.** Mutants (`port_work/p36/mutants.sh`): code-length repeat
base, copy limit `<=`, literal/end-of-block split, link e = j + 17, stored byte + 1, table-size loop: all DIFFER. Two
first-round mutants were equivalent in practice (the `<=`/`<` table-size test, a stored check that can never fire)
and were replaced.
Work area alignment: the tables are written with sh/sw, so the work pointer must be word-aligned (D_8003809C is).

**The browser can drop its TEMPORARY PC inflater** (`web/port/ultra/pc_mem.c` func_1000654C, which ignored the
