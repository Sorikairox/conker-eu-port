## 2. Determinism (task 3)

Without `?det`, three wall-clock inputs reach the game in a Chrome run (all port-side):
1. `osGetCount` / `osGetTime` (pc_os.c) = `performance.now()`. Game code uses the counter as a random source
   (game_36680 func_1500A990, game_3DF10 particle angles, game_39750 66 sites, CD540, 357F0, 40490, 1C1A20 ...),
   and `osSetTimer` timers fire by it.
2. `osAiGetLength` (aud_out.c) = the Web Audio ring level, drained by the ScriptProcessor in wall time (audio
   is `running` in these headless runs), so the audio manager's frame sizes vary per run.
3. `port_sched_run` ends a retrace's thread work after 40 ms of wall time (FRAME_BUDGET_MS).
`?det=1` already removed 1 and 3 but also switched the VI to one retrace per browser tick (game ~20 % fast in
Chrome, screenshot times no longer real time), so routes ran without it.
**Fix (port only):** `?det=2` = det clock + no wall budget + new virtual AI queue (game pushes, drained at the AI
rate per retrace; `aud_out.c det_vq_*`, also active for det=1) while keeping the wall-paced 50 Hz VI.
`p252/route.sh` uses det=2 by default.
**Result:** the same route twice with det=2 (d2a / d2b) gives identical `[p205go]` / `[p174ev]` / `[stub]` /
`[p223hit]` logs (174 lines, only the run end differs); det=1 with `&timer=2` (setTimeout main loop, ~143 retraces/s
= 2.9x real time) gives the same log too, so routes can be tuned fast with det=1&timer=2 and replayed with det=2
for screenshots (same frames). The P248 A/B split (stubs at river entry in B) is gone: both former river-entry
stubs are C now anyway. Which of the three inputs caused A/B was not isolated (no det=0 ablation runs).
