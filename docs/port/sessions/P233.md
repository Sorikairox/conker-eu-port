## 2. ROM_ABS automation: `port/tools/romabs_check.py`

- Lists every `D_<hex>` data symbol the NON_MATCHING C references whose link value is below 0x10000000 (ROM offsets,
  texture ids, physical addresses; 0x10/0x15/0x16xxxxxx are TLB segment data that n64mem.py handles). Sources:
  `port/build/ll/*.c.ll` (the real NM build before vbe.py) plus a source scan of src_eu (NM-side only, comments
  stripped) so new C is seen before the next port build. Link values from the same symbol files as gen_stubs.py.
- Kinds: `absolute` (needs vbe.py `ROM_ABS`) or `alias` (KSEG0 | value is a known RAM data symbol: needs the new
  vbe.py `RAM_ALIAS`). D_2D810 collides with D_8002D4B0 (= 0x8002D810) but is a PI-DMA ROM offset: listed in the
  checker's `REVIEWED_ABS` with the reason (kind `absolute*`).
- Fails on: missing entry, wrong ROM_ABS value, wrong alias target, alias-shaped symbol in ROM_ABS without review.
- First run: **1 FAIL: D_89810** (game_eu_1B1ED0.c shadow pass, `gSPMatrix(&D_89810)`), all 14 ROM_ABS entries OK.
- Fix: `port/tools/vbe.py` `RAM_ALIAS = {'D_89810': 'D_80089810'}`: the external declaration becomes D_80089810 (or is
  dropped when the module already has it) and every `@D_89810` reference is renamed. Build stats: ramalias_decl 1,
  ramalias_ref 1; D_89810 is no longer a zero data stub (data_stubs.c has none). Result: 15 symbols (14 absolute, 1
  alias), **0 FAIL**.

### The null+0x24 writer (store watch)
`watch.sh inst` (wasm-dis, every store wrapped by a checker that traps on [0x24, 0x28), wasm-as) + node run with the
war.env frame script:
1. First trap, **frame 2139** (title / menus): `p161c4 <- func_15163DEC <- func_15160684 <- __port_icall_slow <-
   func_151603FC <- func_151670C0 <- func_15019130 ...`.
2. With func_15163DEC excluded (`SW_EXCL`), next trap right after **frame 6247** (Total War start):
   `p161c4 <- func_15160954 <- func_151607A4 <- __port_icall_slow <- func_151603FC <- func_151670C0`.

**Root cause (game C, owner port): `conker/src_eu/game_18D770.c:106`** `D_8008B0F0[arg0->unkF]()` calls the
struct225 handler table **without arguments** (`conker/include/variables.h:444` declares
`extern s32 (*D_8008B0F0[])(void)`). The asm (func_151603FC at 0x1516096C) leaves arg0 in a0 at the `jalr t9`, and
every handler (func_15160600, func_1516065C, func_15160684, func_151606A8, func_151607A4, ... 16 entries) takes
`struct225 *arg0`. In the port they get 0, so func_15160684 -> func_15163DEC(NULL, &NULL->unk18) stores
`arg1->unkC` at 0x24 (and unk10 at 0x28, unk1C at 0x34), func_151607A4 -> func_15160954(..., NULL) likewise. This is
arity_scan row `func_151603FC D_8008B0F0[...] a0:E` (listed since P75's scan, never fixed). Fix: declare the table
`s32 (*D_8008B0F0[])(struct225 *)` and pass `arg0` (the matching build should stay identical: a0 already holds
arg0; verify_all). func_1511E4F4 is not involved (P227 was right).

## 4. Difftest selftest in conkerdev-web

Cause: **the web worktree had no `port_work/pyuc201`** (gitignored, per worktree). difftest.py prepends that pinned
**Unicorn 2.0.1** to sys.path; without it the container's pip unicorn 2.1.4 is used silently, and 2.1.x
mis-translates a call next to an FPU instruction (P5 finding): the stub's first block faults at pc 0. Shown by
bisect: port's difftest + web files EQUIV, web difftest + port files UNSURE in the same fresh container; the only
script-relative input is `../../../port_work/pyuc201`.
Fix: `docker exec conkerdev-web pip3 install --target /conker/port_work/pyuc201 unicorn==2.0.1.post1` -> selftest
**103 / 103**. `tools/port/difftest/selftest.sh` now stops with an ERROR line (and the install command) when the
pinned copy is missing (unless DIFFTEST_UNICORN is set), so this can't pass silently in a new worktree again.
