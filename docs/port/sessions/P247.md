## 3. MP3 Huffman group (game_eu_226870): draft only

`docs/port/sessions/p247/d_huff_draft.c` (not inserted, not compiled, UNVERIFIED). Findings:
- func_151F9184 (big values) and func_151F933C (count1 quads) have the **normal C ABI**: game_221290 calls them from C
  with 8 / 7 arguments. Only func_151F9060 (Huffman pair: 8-bit lookup in D_800E0E24 [+0x2200 = length], else tree
  walk in D_800E0E20[table]) and func_151F911C (get n bits) use the register ABI, and only 9184 / 933C call them.
  The draft writes 9060 / 911C as static helpers on `HuffReader {buf, pos}`; the asm's a0 is always buf + (t0 >> 3),
  so only the bit position is kept.
- **func_151F94E0 is not part of the group**: compiled float code (no hand-written markers, no calls), the IMDCT /
  hybrid step called from game_221290 with (`&stream->unk4f64[ch][i]`, i, ..., sine_block[..]); convert and difftest it
  on its own (960 words).
- Verification plan: difftest cannot run 9184 / 933C (the reference's jal to 9060 / 911C is stubbed and the stub does
  not follow the register ABI); needs a whole-function harness that runs 0x151F9060..0x151F94E0 for real against the
  C, on the runtime tables and real MP3 frames.
