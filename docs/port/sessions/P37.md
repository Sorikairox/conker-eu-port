## 2. Inflater check (`?infcheck=1`)

`-Wl,--wrap=func_10006530` (the entry that all callers in other TUs use) points to `__wrap_func_10006530` in `pc_mem.c`.

- Before the call, the wrapper inflates the stream into a host buffer with the independent raw-DEFLATE decoder. The
  decoder reads its input through vbe; `inflate_raw2` vbe bit 0 = input, bit 1 = output.
- It then runs the game's C and compares, byte for byte through vbe:
  - the return value against the reference length and the rzip BE u32 header;
  - the output bytes against the reference.
- **Results:**
  - node, 60 s: 64/64 ok, 0 mismatches;
  - Chrome: 64/64 ok, 257640 bytes.
- **Level 0x21 model list:** call #53, inside `func_150031EC(0x21)`. Header 14904, game C 14904, 0 byte differences.
  - `?infcheck=2` brackets the level loader's calls with `[infcheck] level loader func_150031EC(0xNN) begins/ends`, and logs
    every call.
- **Texture 0xED0:**
  - After the level 0x21 load, the wrapper asks the game's own cache for it (`func_1510D66C(0xED0, &sz, 3, 0)`): loaded,
    768 bytes, no mismatch.
  - Asking earlier returns 0, because the cache slots are still 0 rather than −1 before the level init.
- `?infcheck=1` also wraps func_1510D66C and logs any id ≥ 0x1E54 with the JS stack (`[texid]`). None are left.

## 3. Visibility walk on real level data: blocked by three asm functions

`-Wl,--wrap=func_150A5858` (`gfx_f3dex2.c`) does three things:

- **Default:** it calls the game's C, unless the inputs are missing. In that case it logs `[vis] skipped (inputs missing)`
  twice and emits nothing, which is the old stub behaviour.
- **`?vislog=N`:** for the first N calls it logs:
  - source tri slots (0x05: 1, 0x06: 2, 0x10–0x1F: 4);
  - emitted commands and tri slots;
  - set visibility bytes;
  - once, a leaf scan for the P34 `$gp` question.
- **`?dlapprox=1`:** the P31 diagnostic (the whole level DL).

At both levels the inputs are missing. On level 0x25 and on level 0x21: `vis [10906000, 10906000) tree 00000000`.

The chain is all C except the three bold functions, which are asm stubs:

- **Visibility-byte range:** func_15003668 (C) sets `D_800D3668 = D_8003809C`, `D_800D3A8C = D_8003809C + ALIGN8(func_15002878())`.
  - func_15002878 (C) returns the largest per-area triangle count `D_800DBE18[]`.
  - That count is `D_800DBE38`, which **func_15001460** (game_2DF70, asm, 324 lines) counts.
  - func_15001460 walks a level DL (G_VTX 0x01, TRI1 0x05, TRI2 0x06, Rare TRI4 0x1x: vertex indices unpacked from
    5-bit fields). It writes the triangle table `D_800DC26C` (3 vertex pointers per triangle), the bounds `D_800DC270`
    (s16 x0, y0, x1, y1 per triangle) and `D_800DC274`.
- **Node tree:** `D_800DC278 = D_800DBE08[area]` (func_150A4ED4, C, through func_1510F800).
  - func_150038A0 (C) builds it: **func_15001A08** first. This is asm, 66 lines, with a commented JUSTREG draft in
    game_eu_2F180.c. It allocates the node pool D_800B0DDC that func_15001B10 hands out, after a cart-ROM read at
    `0xB0000D24`.
  - Then func_15001BC8 → func_15001DE0 (C quadtree) → **func_15002008** (asm, 144 lines). That is the leaf builder: the
    `node+0xE` index lists that the walk reads.
- **Result:** no level triangles reach the frame without `dlapprox`, and with it there are 288, the whole level DL.
  - The P34 UNVERIFIED item cannot be checked yet: the "previous index" starts at 0 where the asm used the caller's
    `$gp`. `?vislog=1` prints the leaf scan as soon as a tree exists.
