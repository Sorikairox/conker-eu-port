## 1. Why a mechanical translation

The engine is 2110 instructions, counting the triangle / box helpers func_150AA950 .. func_150AB264 it calls. The ray
cast is 873 instructions, counting its vertex loader func_150AD844 and edge test func_150ADBC8. Both are hand-written:
- the helpers pass points, boxes and planes in FPRs (f0-f2 box, f3-f5 point, f19-f22 plane, f23-f31 triangle);
- func_150AAF00 returns through `$t7`, func_150AAB58 through `$t8`, func_150AAB24 through `$t9`;
- the engine keeps its whole state in s0-s7 / fp / gp / f23-f31 across helpers;
- it jumps through 4 continuation pointers that each entry stub stores at sp+0x1D0..0x1DC (map: P53.md §5).

A readable rewrite of ~3000 instructions was not possible in one session. So `asm2c_hand.py` translates the splat
listing one instruction per C statement:
- GPRs are `u32` locals and FPRs a union array `F[32]` (single precision only; FR=0 pairs are not used here);
- branch conditions are evaluated before the delay slot, likely branches run the slot only when taken, and `jr reg`
  reads the register before the slot;
- an internal `jal` sets `ra` to the return address and jumps; `jr` goes to `dispatch`, a binary if-tree over every
  code address a register can hold (return addresses, `%hi/%lo` code labels, the entries). It is not a `switch`,
  because IDO would put a jump table in `.rodata`, which the NM link parks NOLOAD;
- external callees are C calls: func_1507C7C0, func_150A69A8, func_150A49D0, func_150492CC, func_150484A0,
  func_1510F800, sinf, cosf;
- abs.s / neg.s are sign-bit operations, cvt.w.s is round-to-nearest (`nmD5E90_rint`), trunc.w.s is a C cast,
  and div gives the VR4300 divide-by-zero result;
- the `.word` block of func_150AACF4 (splat could not disassemble it) is decoded by the translator; the format
  string inside it is data;
- the asm frame (0x268 bytes for the engine, 0x70 for the ray cast) is a local buffer, and `sp` holds its address.
  The entry functions write the caller's stack arguments at entry sp+0x10.

`ASM2C_TRACE=1 tools/port/gen_d5e90_walls.sh` puts `NMW_TRACE(label)` at every label: a ring buffer at 0x80700000,
for debugging against `Ref.trace`. A code address the dispatch does not know returns 0xBAD00000 | pc; this cannot happen.

Prototypes:
- `s32 func_150AB6D0(f32 x, f32 y, s32 zbits, u8 *rec, s32 mark)` and the same for func_150AC8C4. This matches the
  callers in game_eu_71E70.c. z travels as float bits in a2.
- `s32 func_150ACEA0(f32 x0, y0, z0, dx, dy, dz, s32 a6 .. a13, f32 range)`: o32 arguments. a6 / a7 and a11-a13 are
  out pointers or 0, a8-a10 are the hit x / y / z pointers, and `range` = 0 means 0x10000^3.
- func_150AC8C4 returns at once when rec+0x20 > 0. The asm then leaves the caller's v0; the C returns 0. Both callers
  ignore the result.

## 2. Tests (`nmasm_walls.py`)

Reference: the VR4300 interpreter on build/conker.eu.elf. Candidate: Unicorn on build_nm. The callees run on both
sides. Compared: v0, s0-s7 / gp / sp / fp, and all of RDRAM except the stacks.

Synthetic setups:
- 1-130 triangles around a record: vertical walls, floors, random and degenerate triangles;
- bounds tables (sometimes perturbed) and flags D_800DBE5C (sometimes 0);
- a tree: one leaf, or nmasm_floorsets' random trees;
- area kind 0 / 1, record kinds 0 / 4 / 0x2C (func_1507C7C0 sizes), D_800CC1F8 / 1FC choices;
- moves of 0..200 units, and the mark flag.

For func_150AC8C4 the setups add ledges 62-67 units up with the 0x0E000000 flags. That is the step window
(64 / 65 at sp+0x1E0 / 0x1E4); its hits set D_800CC1C0[rec], D_800CC214 / 218 and D_800CC1B0 / 1B4 / 21C.

For the ray cast, func_1510F800 is stubbed out in synthetic mode, so the area tables stay the synthetic ones.
D_800DBE08 (its tree) = D_800DC278, and D_800DC320 = 0.

Level mode: nmasm_level's pipeline builds the level and func_150A4ED4(area) selects the tables. The record is placed
within 120 units of a real triangle of area 0 / 1. The real func_1510F800 and the world objects run here.

Results (`port_work/p56/runs.log`), all 0 diffs:
- synthetic, seeds 11 / 12 / 13, 400 trials per entry and seed:
  - func_150AB6D0: 147-158 runs return 0 and 242-253 return 1 (moved by a wall);
  - func_150AC8C4: 18-21 step hits per seed;
  - func_150ACEA0: 96-105 hits per seed;
- levels 0x21, 0x1, 0x5, 0xB: 300 trials each, over area 0 / 1 (0x1: 1538 / 23 triangles, 0xB: 1822 / 52; 0x21 / 0x5
  have no area 1):
  - func_150AB6D0: 5-44 % of the runs moved;
  - func_150ACEA0: 14-44 % hit;
  - func_150AC8C4: never fires (none of these areas has triangle flags; D_800DBE5C = 0).

Mutants (`docs/port/sessions/p56/wallmut.py`, `port_work/p56/wallmut.log`). Killed (DIFF):
- step window 65 -> 66 (func_150AC8C4, 10 diffs);
- centre 0.5 -> 0.502 (168 diffs);
- outcode bit 4 dropped (41 diffs);
- ray edge-sign count 3 -> 2 (41 diffs).

Survived:
- visited-list cap 100 -> 99: never reached; it needs more than 99 triangles inside the box in one walk;
- node radius - 1: an exact-boundary case;
- plane flip `!(n >= 0)` -> `n < 0`: differs only for NaN, so equivalent;
- ray direction scale 65536 -> 32768: the hit tests look scale-invariant;
- ray default range 65536^3 -> 65536: the test rays are at most 400 units long;
- ray `s1` (sign of dx) forced to 0: not explained. The ray cast's x-major / sign branches are only partly
  covered, so treat it as UNVERIFIED (§3).

Harness notes:
- EU symbol names are not their addresses (D_800DBE5C is at 0x800DC28C, D_800DBE08 at 0x800DC238): use the ELF symbols.
- The candidate runs on the reference's data image. NM-build callees that read tables only present in the NM layout
  return garbage there: libultra `sinf` / `cosf` and func_150484A0 / func_15048360 (atan2). `patch_libm()` makes the
  candidate's copies jump to the reference's code, with their jal targets re-pointed.
- `.nm_rodata` is NOBITS in the NM ELF. `nmasm_vr.nm_rodata()` now relinks into /tmp with the same script minus NOLOAD
  to get the literals and jump tables. Before P56 the candidate saw zeros there.
- A ray-cast flags pointer (arg 13) with D_800DBE5C == 0 reads address 4 * triangle (a TLB miss on hardware). The
  harness passes 0 there in that case.
