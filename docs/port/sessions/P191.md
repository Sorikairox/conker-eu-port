### func_1504B0FC player_swim_update (the browser blocker, P189)

Called by the C player update func_1504CB98 every frame while `in_water != 0` (arity 2, f32 result read at line
~1833). As an asm stub it did nothing, so the entry buoyancy (gravity -3.0) lifted Conker forever (level 0 noev rise,
level 0x29 control loss at 25889; P189). What it does (surface = +0x118, surface line = surface - 60):
- clears state +0x68 and +0x110; reads the input bytes D_800CC6A4[2] (turn) / [3] (dive) unless stunned / dead /
  state +0x198; state +0x22 >= 0x65 forces dive 0x50.
- shallow float-up (state +0x20 bit 0 or +0x21): air timer 0, y += 8 * D_800D1550 up to depth2 400 (dive <= 10).
- in_water == 1: +0x1CC = y; no surface (-10000) -> func_15052408, return 0; pitch target = dive * 2.25 (below the
  line - 175 and no dive: keep the pitch; 0 with +0x21); func_15059444; stunned (unless dead and vy < 60) or move
  0x262 -> return 0; buoyancy rise y += min(depth2, 300) * dt * 0.002997 (not in move 0x22).
  Other in_water values: gravity / y_velocity zeroed when they have opposite signs.
- bottom contact (in_water 1, +0x28 < 10, y >= line + 20): func_15052408, xz speed <= 16, return it.
- otherwise (in_water 1): surfacing (+0x1A6 above surface - 50 or state +0x20 bit 0, alive) plays the gasp by the air
  timer +0xB2 (>= 0x5D3: sound 0x1A7, >= 0x2D1: 0x168) and resets it; under water the timer grows by D_800BE9E4,
  at 0x605 (or dead without state +0x120) one health is lost (sound 0x499 at 4; at 1 -> death func_1507CD64 3, or
  4 when stunned with gravity 0), warning sound 0x499 between 0x5A1 and 0x5D2 (health < 4); **gravity < 0 with
  y_velocity > 0 -> both 0 (stops the buoyancy)**; bob speed state +0x1C (+0.05 up to 2.5 above line - 175, else 0)
  moves y, **clamp: 0.65 of the excess above line + 14 is removed (bob 0)**; above line - 75 the pitch target -30.
  Then (all in_water != bottom): move 0x22 limits the target to >= -20; floor push (+0x28 < 40: func_1510FDA0 /
  func_1505210C, pitch eased 0.2 towards the floor slope); pitch +0xB8 eases at <= 2.7 * D_800D1550 per frame
  (+0xBC = rate), clamped to -90..90; unless +0x21, the turn ((turn + 8) / 18) * D_800CC264 * 256 / 100 is taken off
  +0x76 (+0x7E = 0x17) and the result is target_speed; +0x80 = 1.
- state +0x95: y = old_y; in_water = 0 unless y stays below the surface line.
Callees are all C (func_15060A30 / func_15059444 game_83300, func_15052408, func_1505210C 78230, func_1507CD64
A9D90, func_1510FDA0). Mutant notes: the 2.7 pitch-rate limit hides pitch-target changes, so the boundary setups
