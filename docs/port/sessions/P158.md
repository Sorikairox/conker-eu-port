## 3. First room (Chrome)

Walk / jump / tail pick-up / pause behave as in P154 (padtongue.py: the jump collects the tail, HUD "3"; START opens
the pause menu; B calls the stub func_15064668). Rendering issues:

### (c) Interlaced pause-menu text and HUD digits: port renderer bug, FIXED
`?p158f=F` (new, see section 5) dumped the pause frame (task 4856, frame 19422). The letters ("PAUSED", "CONT..",
the lives digit) are **RGBA32** textures loaded with `LOAD_BLOCK lrs 1023 dxt 0` (data stored pre-swizzled for
odd rows). The renderer never applied the odd-row swap to 32-bit texels (`texel()`: `if (t->siz != 3 && (y & 1))
a ^= 4`), so every odd row showed its texel pairs swapped: the noisy / interlaced look (P154_12). On the RDP a
32-bit tile keeps 16 bits per texel in each TMEM half and odd rows swap the 32-bit halves of each 64-bit word, i.e.
texel pairs: in the port's linear 4-byte layout that is address ^ 8. Fixed in port/gfx/gfx_f3dex2.c consistently in
`texel()` (^8 for 32-bit), `load_block()` (dxt odd lines of 32-bit loads swap 16-byte texel pairs) and `load_tile()`
(^8). Result: P158_4 / P158_5 (clean letters and HUD digit; before: P158_2 / P158_3).

### (b) Hatched floor patches: port renderer bug, FIXED
They are the projected shadows (shadow_level_triangles, material oth 082C3F/005049D8: Z_CMP without Z_UPD,
ZMODE_XLU, combiner FFE9FF/FFD21F0F, I8 64x64 shadow map). The shadow polygons are clipped copies of the floor
triangles at the same height; GL's LEQUAL on the differently tessellated coplanar polygons z-fights, giving the
hatched rectangles. The RDP's depth compare has a dz tolerance, so on N64 they pass. Fix: draws with z compare and no
z update get the same polygon offset as ZMODE_DEC (-1, -2) (`?p158nozofs=1` restores the old behaviour). Result:
P158_6 / P158_7 (no hatching; the shadow is soft-edged).

### (a) Dark streak from Conker toward the camera: game behaviour, not a port bug
`?p158light=N` (wrap of shadow_light_projection func_151848D8) in gameplay: the shadow lights of level 0x22 are two
light-list entries at **(-435, 91, 239)** and **(281, 91, -414)**, ~500 units from Conker and only 91 units high
(Conker's box is ~100 tall). func_15187820 (shadow level setup, NM C, checked against its asm: `beq a0, 0x22` ->
`sb zero, D_800DE470`) turns the "minimum light height = 0.577 x horizontal distance" rule off for level 0x22
(and 0x21), so the minimum height is 10 and the projection is nearly horizontal: Conker casts two long shadows away
from the two wall lights. The shadow map itself is correct (P158_8: white map, black silhouette; the shadow-level
vertices use t 25..33, the feet rows). After the z fix the two streaks read as soft shadows (P158_6). The darker,
uniform streak in P154_10 was the z-fighting on top of it. Not fixed (nothing to fix); worth a real-hardware
comparison.
Side note: rows 62 / 63 of the 64x63 shadow map are dark (row 63 is outside the 63-row scissor and never rendered;
row 62 is copied from row 63 by the pass's own texrect copy of the image). The tile clamps (cms / cmt 2), so only
texture coordinates beyond row 62 would see it; the clipped shadow polygons stay inside.

### Other renderer finding (not fixed)
The pause screen background is black: the menu draws the frozen frame from the colour image at 0x1065B180 (292 wide
RGBA16, LOADTILE strips, env alpha 0x80), but the port renders the main frame only in GL and never writes it back to
RDRAM, so the game reads an empty image. Fix idea: read the canvas back into the colour image when the game freezes
the frame (only on the pause transition, a per-frame glReadPixels is too slow).
