## 1. func_151E3AE4 (settings_list_draw): real bug, fixed

P134's 20 "a1" setups DIFFER with `DIFFTEST_ARGMEM=15049AD0=0:52` (x[0] ref 83.0, cand 74.0). Cause: in the asm frame
the ring arrays are **y at sp+0x90 with only 14 slots and x right behind it at sp+0xC8** (32 slots). With 13 or more
shown items, y[14..] lands on x[0..]: the wrap `y[count + 1] = y[1]` (count = 13) overwrites x[0] with y[1] = 83, and
layout writes y[i] for i >= 14 also overwrite early x[] entries. The P120 C had two separate 32-entry arrays.
Fix (NM): one `f32 points[14 + 32]` with `y = points`, `x = points + 14`, same store order as the asm (comment in
the code). Any settings set with 13+ shown items (ring layout, arg1 != 0) uses the clobbered point in the game too; the
item masks D_800ABB38 were not read from the ROM here.

Verification: the 68 P120-errored setups with ARGMEM 0:52: **68 EQUIV** (old: 48 EQUIV / 20 DIFFER,
`port_work/p134/3ae4_err_argmem.log`); P120 setups without ARGMEM: 479 of 614 run, all EQUIV (run stopped for
budget; `port_work/p138/3ae4_all.log`). ARGMEM 0:128 is useless here (it reads unwritten slots past count + 2:
stack garbage, false DIFFER) - keep 0:52. Aliasing mutant (`x = points + 18`, `p138/3ae4_muts_alias.txt`) killed
with ARGMEM 0:52. The P120 mutant lists were not re-run (stopped for budget; only the array layout changed).
