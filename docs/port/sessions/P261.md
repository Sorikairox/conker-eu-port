## 1. The lever in code (gate_swing_update func_151184BC, game_eu_142E40.c)
World object 10 (P248 "GATE") is the lever arm. Level 1 / 0x29 case: handle offset (-13, 76, 354) * scale, rotated
by the arm angle +0x0 then yaw +0x4 (func_15118324), plus pos +0x10. Object 10 (yaw -97, pos 2365 1961 -2636) puts
the handle at **(2015, 2037, -2692)**, about 300 above the rim path (y 1712..1734), hanging over the chasm edge.
Grab condition (each tick, state not 1/3), for each player record (D_800CC2D0, D_8008FD8C of them):
- not busy: rec +0x65 == 0, +0x104 == 0, ctx(+0x31C) +0x17 == 0, +0x27 == 0, ctx +0x6B < 4;
- feet below the handle: rec y (+0x18) + 40 < handle y;
- head near the handle: (x, y + s16 rec+0xE6, z) within sqrt(reach) of the handle; reach = 10000 * sz^2 on 0x29
  (**distance 100**). Conker's +0xE6 = 48 (head 48 above the feet).
So it is **jump-and-hang**: Conker's head must come within 100 of the handle, i.e. a jump with the apex right under
it (head ~1945 at the apex from the ledge, so horizontally within ~40). Then ctx +0x6B = 1 (50-tick wait) -> 2,
ctx +0x6C..+0x70 = handle position each tick (the player code hangs Conker there), the arm swings +0x0 0 -> 40
degrees (speed +0x84, accel +0x80), the handle goes down by ~245 with him, state 3 at 40 (sound 0x14), then it
swings back (state 1 -> 0) when he lets go.
**Link to the doors**: not in the gate code. Doors 8 / 9 (mover_swing_step func_15118F2C / func_1511FF00) went to
state 2 (opening) on the same tick the arm reached 40 (frame 12589, with event 10CC act6 id 9000 = camera, and the
new stub func_15097188) and to state 3 (open) at 13005. The link is in code outside these two (func_1511BAA4 /
func_1511ADC0 write world-record +0x73; not traced).
