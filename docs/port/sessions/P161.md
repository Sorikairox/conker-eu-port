## 1. The null+0x14 = 0x400 writer: func_1501370C drops its argument (game C)

**Method: a store watch on the whole wasm** (new, reusable). `wasm-dis conker.wasm` (binaryen in conker-emsdk,
`/emsdk/upstream/bin`), `storewatch_inst.py` wraps the address operand of every store (101250) in a call to a
checker that traps (`unreachable`) when the store touches wasm 0x14..0x17, `wasm-as -all -g`, then a node new-game run
of that wasm (`nrun.sh` with the web dir overlay, `PORT_PADF` = the two STARTs 3386 / 4458). The trap's stack names the
store. Runs about as fast as the normal build. Change the range in the script for other addresses.

Result (run w2, frame 4559 -> 4560, right after func_15000AD0 at the new-game level load):

```
p161c1 (byte store) <- func_1501374C <- __port_icall_slow <- func_1501370C <- __port_icall_slow <- func_15013000
  <- func_15007B3C <- func_15007830 <- func_10001194
```

- **Writer**: `func_1501374C` (conker/src_eu/game_40490.c:74): `arg0->unk16 |= 4; func_1515D088(arg0);` called with
  arg0 = NULL. Byte 0x16 = 4 is the BE word null+0x14 = 0x00000400.
- **Cause, not a stubbed producer**: `func_1501370C` (game_40490.c:64) calls `D_80082EA0[arg0->unk17]()` with **no
  argument**. Its asm (`lbu v0, 23(a0)` ... `jalr v1`) never touches a0, so on N64 the handler gets the record. In the
  port the icall passes 0. Same bug class as func_1501396C (fixed in P76, three lines below). Already listed in
  `docs/port/arity_scan.tsv` row 22 (`func_1501370C D_80082EA0[func_1501374C,func_15013778,func_151C7750,func_15013FC4,+1] ... a0:E`).
- Caller chain: func_15013000 (level-start pass over the D_800D34B8 records, 0x34 bytes, D_800D3094 of them; handler
  D_800831C0[rec->unk15 >> 2]) -> handler 0 = func_1501370C -> D_80082EA0[rec->unk17].
- **Not harmless**: every D_80082EA0 handler gets NULL at level start. func_1501374C: the record never gets flag 4 in
  +0x16, and func_1515D088(NULL) (game_1897A0.c:121) reads NULL[6] (0) and spawns a type-0x11 effect whose owner
  pointer is NULL. func_15013778 (record effect spawn) reads radius NULL+8 = 0 and spawns nothing. The other handlers
  (func_151C7750, func_15013FC4, +1) also get NULL.
- **Fix to make in game C** (game_40490.c func_1501370C, as func_1501396C):
  `void (*func)(struct16 *) = (void (*)(struct16 *)) D_80082EA0[idx]; if (func != NULL) func(arg0);`
- Test, port side: `?p161fix=1` / `PORT_P161FIX=1` (`__wrap_func_1501370C`, gfx_f3dex2.c) passes the record. Node run fx
  (new game, control reached, run to retrace ~22800): **null zone 0 dirty words** (default build: 1, null+0x14), heap 0
  errors. It exposes a new stub: **func_151530A8 (game_eu_17D3C0.c), 102 calls from frame 4773**, reached through the
  now-real record handlers (func_1515D088's effect). By the producers-before-consumers rule the game C fix should go in
  with func_151530A8 converted (or at least checked with stubcalls.py).

## 2. Pause-screen background (port/gfx/gfx_f3dex2.c)

What the game does (log chS, `?p161log=F`): in the first paused frame it sets **SETCIMG = the z-buffer image**
(292 wide RGBA16, e.g. 10B0B180) and copies the previous screen image (LOADTILE strips, 1:1) into it; then it draws the
z image onto the screen image. Later paused frames texture the frozen frame from the z image (P158's 1065B180 was the
z image of that build). Two port gaps:

1. Screen images exist only on the GL canvas: RDRAM never had the previous frame. **Fix (fbc)**: at the end of every gfx
   task whose colour image is a screen image (>= 256 wide, 16-bit, not the z image, not offscreen) the canvas is copied
   into a GL texture per image address (glCopyTexSubImage2D, GPU only, 4 slots). A SETTIMG inside one of those images
   (other than the one being drawn) reads the copy back once (glReadPixels only then; `dirty` flag) and writes it as
   RGBA5551 BE in N64 pixels (VI rows, P147). Log chP: written back once at the pause (frame 19318), mean rgb 36.
2. SETCIMG of the z image was treated as "depth clear" only and its draws went onto the canvas. **Fix (off_zimg)**: a
   16-bit SETCIMG of the z image (<= 320 wide) is now a P137 offscreen image with its own FBO (320 x 256, allocated
   once); its z-clear fill rectangles still clear the canvas depth (bind 0, clear, rebind) and it is written back to
   RDRAM only if something was drawn into it (`off_drawn`), so the per-frame depth-clear passes cost a bind and no
   readback. The noev run logged 0 z-image write-backs (the [p140] "written back" log line prints on every off_end, even
   when the write-back is skipped).
3. Also added: `fbc_restore`: when a task first selects a screen image that has a copy, the copy is blitted onto the
   canvas (the RDP image keeps its pixels between frames, the canvas is cleared at every task). It was not what the
   pause needed, but it is N64 behaviour (one full-screen blit per task). `?p161norestore=1` = off.

Flags: `?p161nofb=1` (no copies / write-back / restore), `?p161nozc=1` (z image not offscreen), `?p161norestore=1`,
`?p161log=F` (log copies, texture hits, SETCIMG / SETTIMG >= 256 wide from retrace F, 200 lines).

Screenshots (docs/port/sessions/p161/): P161_1 before (chP, write-back only, black, as P158_4); **P161_2 after (chU 396 s:
the frozen first-room frame behind PAUSED / CONT.., darkened)**; P161_3 the frame before the pause (chU 372 s);
P161_4 noev walk after (50 s). The paused image looks zoomed / softer than the live frame: that is the game's own
pause effect as far as the DL shows (strips drawn with the frozen frame as texture); not compared with hardware.
