Who writes it (`?p113watch` on slot 0 +0x64, then a queue dump in the func_1502457C wrap): at frame 1461 the scene
walker queues **track 4's** event `5/0x3D b4 0 b5 9 w6 1` (attach to object id 1) as **track 1**. Track 1's ref is
object id 1 (Conker), so handler A attaches Conker to himself. At frame 1629 the `b4 1` event clears it.

**Root cause: game C func_1502457C (game_eu_51190.c, P15 m2c body, NON_MATCHING), two pointer-arithmetic bugs:**
- `var_s6 = (arg1 * 0x78) + &D_800C3AA8;` - `&D_800C3AA8` is an `s32 *`, so the slot offset is 4x too big (slot 1 only).
- `var_s6 += 4;` - `var_s6` is a `u8 **`, so each track advances 4 pointers (asm: `addiu $s6, $s6, 4` = 1 pointer).
- Effect: event track i walks the events of track 4i, with the count of track i and the object of track i.
  Track 13 (t = 1700: `3/0xD` camera switch, `5/0x67` exit) is never walked.
- Fix (2 lines, for a conversion slot; not done here, game C):
  `var_s6 = (u8 **) ((u8 *) &D_800C3AA8 + arg1 * 0x78);` and `var_s6 += 1;`.

The tables themselves are right (dump in the log: 15 tracks, refs as scdis prints them).
