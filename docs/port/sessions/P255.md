## 2. HARNESS= registry knob (port-b P251 request)
- `tools/port/reverify.sh`: knob `HARNESS=cmd` (commas = spaces) runs a whole-function harness instead of the random /
  setup / difftest-mutant phases; `HMUT=cmd` (MUT=1) runs its mutant runner. HARNESS must print a verdict line
  (EQUIV / DIFFER / UNSURE / ERROR, or `RESULT X`); HMUT a last line `done: killed K survived S other O` (+ optional
  `SURVIVED k: expr` / `NOAPPLY|INVALID|ERROR k: expr` lines, listed as [expr]). Output: `  harness: VERDICT ...`,
  `  muts harness: K killed / N (survived: [..])`. reverify_all.sh prints `random harness EQUIV` for such rows.
- `tools/port/nmharness.sh SCRIPT [ARGS]`: NM build (NOBUILD=1 skips), runs `python3 ../SCRIPT ARGS` in $CONKERDEV from
  /conker/conker (the nmasm_*.py convention), prints `VERDICT name: line`; harnesses without a verdict word fall back
  to `diffs N` / `N differences` (0 = EQUIV), a traceback is ERROR.
- `tools/port/nmharness_mut.sh SRC MUTFILE SCRIPT [ARGS]`: generalised port-b p251/mhuff.sh: per sed mutant (a `% ...`
  tail is ignored) edits SRC in place, rebuilds NM, runs nmharness.sh, restores SRC (also on INT/TERM), final NM
  rebuild. Never run it during verify_all.sh. Lesson (first test): restoring with `cp -p` kept the original mtime, so
  make did not rebuild and build_nm kept the LAST MUTANT (a later plain harness run showed 16 / 50 diffs); now `cp` +
  `touch`. If a mutant run is interrupted hard, touch SRC and rebuild NM.
- Test row: func_150A44A4 (game_eu_D1760, floor height; `HARNESS=tools/port/nmharness.sh,tools/port/difftest/nmasm_floor.py,400,1`,
  `HMUT=tools/port/nmharness_mut.sh,conker/src_eu/game_eu_D1760.c,docs/port/sessions/p255/150A44A4_hmuts.txt,tools/port/difftest/nmasm_floor.py,200,1`):
  harness EQUIV (400 trials, 0 diffs); mutants 2 / 3 killed. The survivor is presumably the `i = 9` start of the
  packed-bytes zero check (inputs with only byte 8 non-zero are rare in nmasm_floor.py): a harness coverage gap.
- For port-b's MP3 row: `HARNESS=tools/port/nmharness.sh,docs/port/sessions/p251/nmasm_huff.py,../baserom.eu.z64,400,600,7`
  should work as is (its `RESULT EQUIV` line is read); its mutants use mhuff_apply.py's own format, so either keep
