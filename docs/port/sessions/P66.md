- **func_1000480C as C needed one port fix: osRomBase.** The C reads `CART_WORD(devAddr | D_80000308)` =
  `*(vu32 *)(addr | 0xA0000000)`. vbe.py's P42 computed-IO_READ rule already turns that volatile load into
  `__port_io_read(addr)`, and the register model answers the cart domain 0xB0000000.. with the big-endian ROM word
  (PI_STATUS_REG reads idle, so the busy-waits pass). But the port never set **osRomBase (D_80000308)**: it was 0, so
  the C read KSEG1 *RDRAM* 0xA0BB9E40.. (`[io] first read of RCP register 0xA0BB9E40`), the key frames came back 0
  and the first boot crashed in `nmAnimDecode` ← func_150A86B0 (*memory access out of bounds*). `port/boot/game_main.c`
  now sets `D_80000308 = 0xB0000000` with the other IPL3 globals; the log shows `[io] cart read 0xB0BB9E40 =
  0x001DFD2D` and the animations run. The other osRomBase users are unaffected (func_15001A08 ORs 0xB0000D24 anyway;
  the PC osPiRawReadIo / rom_copy mask the cart offset).
- **Clean rebuild** (census + vbe stamp cleared): 722 census TUs, 719 ok (new: nm_asm/D5E90_mtx.c; the 3 FAILs are the old debugger_257350.c,
