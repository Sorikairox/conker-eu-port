## 2. The frame display list now runs end to end

**Root cause of the empty frames:** `func_1501878C` builds about 120 commands of frame DL. Then
`func_eu_1501C860` checks that the write pointer `D_800BE9D0` lies in the buffer
(`n < 0 || cap < n`). If it does not, the function **throws the frame away**: it rebuilds the 5-command
prefix (`func_1501A39C`) and appends only fullsync and end. That is the 12-command DL that P19 and P21
saw. The pointer left the buffer because DL builders that are still asm returned 0.

A new tracer, `gdltrack=N` (§4), showed the step-by-step trajectory. `D_800BE9D0` stayed in the buffer
(0x1060C298 → 0x1060C498) until the stubs `func_1517E7FC` / `func_15182450` / `func_1517FAD4` /
`func_1508FD38` (nested calls in `func_150198FC`) returned 0. After those, it read 0xF0.

Fixes (`gen_stubs.py`, `icall.py`, `icall_gen.py`, `pc_os.c`):
1. **Indirect pass-through.** A site `x = fp(x, ...)` has a pointer result and a pointer first argument.
   At -O0 IR this shows as the first argument loaded from the slot the result is stored to. Such a site
   now gets a `.pt` trampoline: when the target is an asm stub, the trampoline returns `a0`.
   - The stub test is `__port_is_stub(fp)`, a binary search over the 1162 asm stubs, generated into
     `icall_tab.c`. Alias forwarders are excluded.
   - There are 9 such sites; `func_151E8620` → `D_80090370[11]` = `func_151EC300` is the one on the
     frame path. Note: P21 named `func_151EC11C`, but that is `D_800903A4[8]`; `D_800E0B94` is 11 here.
2. **Prototype pass-through.** A stub declared anywhere as `Gfx *f(Gfx *, ...)` returns `a0`. Example:
   `func_1510BF50`, used as `return func_1510BF50(gdl, ...)`.
3. **DL-range pass-through, for the shapes that no source scan sees** (`f(g(x))`,
   `t = f(x); y = h(t)`). Every int stub with an int first argument now ends in
   `return port_stub_dlret(a0)`. This returns `a0` when it points into the frame DL buffers
   `D_800BEDE8[0] .. D_800BEDE8[1] + (D_800BEDE8[1] - D_800BEDE8[0])`, and 0 as before otherwise.
   298 stubs have this form.

**Result:**

- The null zone went from 80 dirty words to 6: the frame DL used to be written at NULL after the
  `func_151E8620` return.

## 4. New debug flags

| flag | effect |
|---|---|
| `dltrace=N` | Dumps every command of gfx task N (the first 2 tasks are always dumped). |
| `dlstat=N` | Logs every N tasks: the opcode histogram, segment references, and `[probe]` (`D_800BEA35`, `D_800BEAC0`, `D_800E0B94`, GDL `D_800BE9D0`, prefix ends `D_800BE9D8`, buffers `D_800BEDE8`). Frames 1–6 and every 120th always log the histogram. |
| `gdltrack=N` | For VI frames N..N+7: every stub hit with its thread and the frame-DL write pointer. This finds the stub where the DL pointer goes bad. |
