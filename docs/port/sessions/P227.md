## 3. Total War null+0x24 write (coordinator request) and func_1511E4F4
- func_1511E4F4 is the per-frame callback of world objects of type 0x28 (floating pickups): it lazily allocates a
  0x10-byte state into obj +0x7C, zeroes the scales +0x2C..+0x34 and animates them, bobs / spins the object and lets
  a player take it (func_1511E320 / func_151D6F20). It has no store at +0x24 of any pointer (stores: obj +0, +4,
  +0x18, +0x2C..+0x34, +0x6E, +0x7C, +0x80; state +0..+0xC) and returns nothing the dispatcher uses.
- So the stub cannot itself have produced `null+0x24 = 7.58f`; the stub entry is only where the browser check ran.
  The write happened earlier in the frame. With the stub, pickups keep their placement scales (+0x2C..) and never
  get a +0x7C state, so a consumer of a type-0x28 object's +0x7C (if any reads it as a larger record) would see
  NULL; no such reader was found in game_eu_142E40.c. Conversion is not expected to fix the write; re-check in
  the browser after merge (UNVERIFIED).
