## 3. func_1508B704 and the 0x8008B4AC table
- **func_1508B704 `rail_zone_flood`** (B7840): recursive flood fill over the rail node graph D_800D2778 (0x10-byte nodes,
  five neighbour bytes at +9..+0xD, 0xFF = none). Nodes outside the zone radius are collected (up to 8, with their
  squared distance as limit); nodes inside recurse into unvisited neighbours. The visited bit is
  `rest[node >> 3] |= 1 << (node & 3)` in the game (mask 3, not 7: nodes share bits; kept). Only caller: the C
  func_1508B854 (ignores v0; void). Parameter `u8 node` (the asm masks a0 with 0xFF).
- **Table 0x8008B4AC**: P246's address was off. The table is D_8008B490 (US name D_8008B0F0, 24 entries); 0x8008B4AC
  is entry 7 (func_151B99B8) and func_150EB3A4 is entry 19 (0x8008B4DC). Dispatcher: **func_151603FC** (game_18D770.c):
  `D_8008B0F0[effect->unkF](effect) == 0` ends the effect, so the entry signature is `s32 (struct225 *)` and the
  result is used. func_150EB3A4 `s32 (u8 *)` is right. Mismatch found: **func_15190940** (entry 18, port-b's
  game_eu_1BAF40.c, matched C) is declared `void` but returns func_15163F50's v0 (it tail-calls it); under NM it should
  be `s32` returning func_15163F50(...) (same case as handler 10, game_18D770.c line ~817). Left for port-b.
