## 3. Runtime checks of the P38 C (`?p38check=N`, `PORT_P38CHECK=N`)

These are link-time wraps in `gfx_f3dex2.c` (`-Wl,--wrap=` for func_15186D04, func_1504A730 and func_150A6840).

- **func_15186D04 (shadows):**
  - The wrapper takes an opcode histogram of the appended DL (VTX / TRI1 / TRI2 / TRI4 / other) and the triangle slots
    per vertex load, which is the splitter's output. Totals are logged every 64 calls.
  - Result: about 1 call per 4 VI frames, and every call appends **0 commands**.
  - Why: object 0 (`state 1`) fails the filter at **`+0x1D4 == NULL`**. Objects 1..7 have `state 0`, and the mask
    D_800DF510 is 0.
  - `+0x1D4` is set only by func_1502E228, reached as func_1502C1D4 (a per-frame stub) → func_1502C074 →
    func_1502E228 (all game_eu_595D0, asm).
  - **The strip splitter (P38 UNVERIFIED: `t2 >= 4` vs `>= 3`) is still unverified.** It cannot run until func_1502C1D4
    and its callees exist.
- **func_1504A730 (objects):**
  - The wrapper logs D_800CC6A4 after each call and flags a value left in the callee's dead frame.
  - Result: D_800CC6A4 = 0x105C6B68 (`D_800BE728[0][0]`, the slot-0 pad record), and it is **never left in the stack**.
  - The stack-buffer branch needs `4 <= i < D_8008FD8C`. D_8008FD8C (player slots) is 1, so the branch is
    unreachable in one-player play. No bug.
  - Note: `sp5C` is `s32[2]`, 8 bytes, and `bzero` clears 6, which is fine.
  - The per-object callback func_1504CB98 is reached through `__port_icall_slow`.
- **func_150A6840 (view test):**

  - Result: **not called** in 30 s, in node or Chrome. The callers are func_150829C0 (spawn, C), func_15035A04 (NM C),
