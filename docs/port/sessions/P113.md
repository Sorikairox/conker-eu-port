## 2. LogoScreen scene end: the corruption stays, the cause is the camera

`?p103boot=1`, idle, events on (no `p110noev`). The scene runs from frame 722 to 2133 as in P110. Then:
- func_15060F28 (from func_1502298C) removes the scene object 105DF6F0. func_150849C0 and func_15060D54 now run
  as C. One new stub is hit: **func_15084814** (game_eu_AF2A0), called from func_150847B4 < func_150849C0.
- The heap was still corrupt at frame 2137: block 43 has float words in its header.

How it was found (all port-side diagnostics, still in the build):
1. func_15084814 emulated (wrap, the asm read by hand: per part j, both words +0x28C + j*8 are either the shared
   block D_800D19A0[slot], so D_800D1F80[slot]--, or freed with func_100043B4(w, 3), then cleared). The corruption
   is the same, so this function is **not** the cause. The wrap stays as opt-in `?p113g84=1`.
2. `?p69free=1`: no double free.
3. `?p113free=FRAME`: logs every free from that frame on, with a heap walk before it. At frame 2133,
   func_15060F28 frees 5 blocks of the object. The last one is the +0x31C record (1065358C, size 0x1C8). The heap
   is clean after every one of these frees.
4. `?p113watch=ADDR&p113wf=FRAME`: watches 16 bytes at every osSetIntMask, every thread switch and the
   checkpoint wraps (below). In frame 2137 the corrupted header (106536C4 = the old record + 0x138) is rewritten
   with floats (3CB33FB6 43FDFCD1 C60FC000 C3173317) **inside func_15122AE0**, the camera update called by
   func_15019130.
5. The hook scans the camera record and finds **D_800DBFF0[0].unk3D4 == 1065358C**, the freed record.
   - unk3D4 is the camera target, set by func_1512868C from `D_800CC2D0[unk23D].unk31C`.
   - So func_15122AE0 -> func_15122C5C keeps updating the removed object's record after it was freed.
   - The next allocation, func_10004250 from func_15019130, then traps.

Producer: nothing retargets the camera when the scene object goes. On N64, LogoScreen should leave level 0x21
through scene opcode 0x67 in the scene VM func_15024910 (-> func_151DECB4 -> mode 3, P103 / P112). func_15024910
is still an asm stub, so that never happens and the camera outlives its target. The exact N64 instruction that
retargets or drops the camera at this point is not identified (UNVERIFIED). Candidates: the scene VM
func_15024910 / func_15029EA8, the scene cleanup.

**TEMPORARY guard** (`port/gfx/p103_boot.c`, `--wrap=func_15060F28`):
- After the real removal, if a camera D_800DBFF0[i].unk3D4 (struct108 stride 0x9A0) still points at the
  object's freed +0x31C record, it is pointed at a zeroed static parking record. One line is logged.
- `?p113noguard=1` / `PORT_P113NOGUARD=1` turns it off.
- Limit: the wrap only sees calls from other TUs. Calls inside game_83300.c (func_15060F28 is called 3 times
  there) are not guarded.

Result with the guard:
- Node idle, 150 s (`post.log`): 7771 scheduler frames, heap 0 errors, null zone 0, no trap. 42 stubs.
- Chrome real time (`logo/`): the scene, then black; heap 0, no trap.
