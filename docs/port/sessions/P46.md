## 1. The level colour: game_36680.c was not in the build

- New flag `?lvlcol=N` (`gfx_f3dex2.c`): logs the first N changes of the BG start colour (the F3DEXBG record M).
- After the merge, with no `lvlwhite`: `[lvlcol] BG start colour 000000 (M 1), frame 725`. That is a black level.
- func_1515E7E8 (P43) takes `col` from a colour zone (D_800DCD80 list), or from the level colour **D_800DCD20**.
  D_800DCD20 is written only by func_1515D4D4. Its callers include **func_150091D0** (`game_36680.c:18`:
  `func_1515D4D4(255, 255, 255, 0)`, plus D_800DCD24 / 28 / 30, the light init at level load).
- `port/build/census/files.tsv` showed game_36680.c as **FAIL** in build mode. Its two errors are at lines 376 and
  382: `u8 sp1C[4] = D_80095B70;` (func_1500A2AC) and `u8 sp1C[2] = D_80095B74;` (func_1500A2F4). IDO copies the
  array from the data symbol; clang rejects it ("array initializer must be an initializer list"). The whole TU fell
  out, so func_150091D0 was the stub `[stub 5] func_150091D0 (absolute)`.
- **Fix: `srcfix.py` kind `arrinit`.** `T a[N] = SYM;` becomes `T a[N]; { element-wise copy from &SYM }`. The copy uses
  the array's element type, so the vbe pass word-swaps both sides like any other access. srcfix now builds 2 TUs:
  game_36680.c and **game_2062D0.c** (15 errors of the same kind, `u8 tmp[3] = D_800AB340;` and so on).
- Result: `[lvlcol] BG start colour 262626 (M 3), frame 725`: a dim ambient plus 3 point lights. 0x26 is not
  0xFF scaled by func_1515E7E8's quarter steps, so it comes from a colour zone or from another level setter
  (game_36680.c:95 `func_1515D4D4(sp70, sp6C, sp68, 0)`). That is plausible level data. **UNVERIFIED** against an
  emulator frame.
- Still failing in build mode (not on any path seen so far): `game_A28B0.c` (`((u8 *)X->unk218) += 1;`, a compound
  lvalue cast that srcfix's `LCAST` does not match), `init_2070.c` and `debugger_257350.c` (`PUT(fmt, s - fmt)`:
  `const unsigned char *` minus `const char *`).

**For the port branch:** `game_36680.c` and `game_2062D0.c` use IDO array initializers from symbols
(`u8 x[N] = D_...;`). They build on the PC only through srcfix. If they get NON_MATCHING bodies, write them with an
explicit copy.

    `call void @func_1512A390(ptr %0)`; vbe stats show `a0_keep=1`. **Remove the entry when port-b fixes the call in
    source** (`func_1512A390(arg0);`).
  - func_15127FEC was not reached in 40 s (`[mem] null zone: 0 dirty words` before and after).
- **func_1509BE40 → D_80088838[k](id, arg, D_800D3380)**, called as `s32 (*)(s32, s32, s32 *)`. The icall layer
