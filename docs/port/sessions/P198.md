## 1. Harness gap: memory written by stubs was not compared (fixed)
- Finding: difftest's final memory compare (and the per-call `mem` hash) is built from `Run.writes`, which only the
  Unicorn write hook fills. Stub knobs (DIFFTEST_OUTW / OUTA / OUTB) write with `mu.mem_write`, which fires no hook, so
  a word a stub clobbered was compared with the value of the function's own last store (or not at all). A mutant that
  drops the restore of a stub-clobbered word therefore compared equal: func_15063254's +0xB8 / +0xC4 / +0x318
  restores survived even with the OUTW `@ADDR` clobber on func_15060F28 (jal 150612D4); only restores re-read later
  (+0x18 -> +0x1CC) were killed. OUTW writes were not excluded on purpose; they were simply invisible.
- Fix (tools/port/difftest/difftest.py): new `Run.stub_write()` used by OUTW / OUTA / OUTB: writes memory and logs the
  bytes in `writes` (same stack / scratch exclusion as the hook), so final memory = what is really in memory after
  stubs. `DIFFTEST_STUBW_OLD=1` = old behaviour (forwarded by tools/port/difftest.sh).
- Selftest: case `cases/func_15063254.c` (P196 candidate) with the k0 setup (object 0 + OUTW clobbers of +0xB8 /
  +0xC4 / +0x318): EQUIV as is; the "drop +0xC4 restore" mutant DIFFER (new), EQUIV with DIFFTEST_STUBW_OLD=1 (old
  miss). selftest 68 ok, 0 failed.
- func_15063254 re-run: all 16 mutants now killed (the 3 P196 survivors by k0: memory differs at the restored word).
  The other setups stay EQUIV.
