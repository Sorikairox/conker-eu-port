## 1. Selftest 118 / 123: root cause

The 5 failing `chkce` cases (func_151416E8, func_15103828 x2, func_15031C1C x2) all write their sed mutant to the
same path `conker/build/difftest_self/FUNC.mut.c` that an earlier case of the same function had already written and
the container had already read. **After the Docker Desktop restart (P256), the container's bind-mount view
(Docker Desktop file sharing, `fakeowner` mount) kept the OLD size and content of a file that the host rewrote under
the same path.** The candidate was read truncated (e.g. host 695 bytes, container 308 bytes, the md5 of an older
mutant), so the spliced TU ended in the middle of a statement and cfe gave "Syntax Error" (CERR).

Evidence:
- Same mutant written to a new path (`port_work/p260/m.c`): DIFFER as expected. Same file at the selftest path: CERR.
- `docker exec ... wc -c` / `md5sum` of the selftest path: 308 bytes, old md5; host: 695 bytes.
- Minimal repro: write a file, `cat` it in the container, rewrite it with a different size on the host: the container
  reads the old size for > 100 s (tested at 0 / 5 / 30 / 70 s). A host `touch` does not help; the Edit tool's
  rename-write does not help either (the container showed the old 9 bytes of a 33-byte file). Listing the parent
  directory **in the container** with `ls -l` (readdir + stat of the entries) refreshes the entry; an `O_DIRECT`
  read sees the new data.
- It also hit a game TU: after this session's edit of `src_eu/game_161520.c` the first difftest of func_151349D0 was
  CERR because the container read 78537 of the 81452 bytes (difftest.py splices the candidate into the TU text).
- Comparison runs: selftest with the fix 124 / 124; the same tree with the guard disabled (`DIFFTEST_FCHK_OLD=1`)
  118 ok / 6 failed: the same 5 cases plus the new regression case.
- Not the other suspects: the pinned Unicorn is there (`port_work/pyuc201`, 2.0.1), the job-limiter slot dir is fine
  (jobs ran), no stale build/difftest files (the generated file is rewritten each run), no locale / sed issue (the
  host mutant files were correct).
- Docker Desktop 4.73.0 (installed May 2026, not updated by the restart). Why it worked before the restart is not
  known; the behaviour is a property of the running Docker VM's file sharing.

Make builds were not visibly affected (make lists the source directories, which refreshes the entries; verify_all
rc 0 and NM rc 0 with a host / container size check before them), but anything in the container that opens a path
without listing its directory (difftest.py reading TUs and candidates, python tools) can read stale data.

## 2. Fix and guards

- `tools/port/difftest.sh` (P260 stale-file guard): before the job starts, in the container it lists (`ls -l`)
  `src_eu`, `src_eu/*`, `include` and the parent dir of every file argument (refresh), compares the md5 of every file
  argument with the host's md5, and compares a digest of the `src_eu/*.c` size list with the host's. A mismatch
  prints `ERROR difftest.sh: stale container view of ...: Docker file-sharing cache, see P260` and exits 4, instead
  of a misleading CERR or result. `DIFFTEST_FCHK_OLD=1` = old behaviour. difftest.py is unchanged.
- `tools/port/difftest/selftest.sh`: a preflight (pinned Unicorn 2.0.1 in port_work/pyuc201, counted as a FAIL when
  missing, with the install command), docker PATH export, and a regression case: rewrite a candidate path the
  container already read, then expect the DIFFER mutant (was CERR). Selftest now 124 cases.
- `port_work/p260/checks.sh`: refreshes the view (`ls -lR` of src_eu / src / include / tools in the container) and
  records `view ok` / `VIEW STALE` (host vs container size digest of src_eu + src) before verify_all and the NM build.
