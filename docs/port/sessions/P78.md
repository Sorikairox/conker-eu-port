## Result summary

1. **Texture blur:** the near-field smear in the grass field is **not a sampling bug**. It is magnification that is in
   the level data, as the per-material dump shows (§1):
   - the textures are 32x32 / 64x32 CI8 / CI4 tiles;
   - the UVs are planar, about 9.4 world units per texel;
   - the near ground is drawn at **0.07-0.43 texels per N64 pixel**, i.e. 2-15 N64 pixels per texel;
   - some wall / lip pieces have UVs 4x stretched along one axis (in the data).

   A split-screen check (old LOD on the left half, new on the right) shows the field is mip 0 either way. The dump did
   find **real RDP-semantics bugs in the LOD path**. They are fixed in `port/gfx/gfx_f3dex2.c`:
   - **(a)** `uPixScale` was inverted (cimg / canvas instead of canvas / cimg). So lod was ~4.8x too small at 640 / 292,
     and distant LOD surfaces sampled 2+ mip levels too fine (noisy, over-sharp far grass next to the soft near
     ground).
   - **(b)** lod used the vector length. The RDP uses the largest of |ds|, |dt| over an x step and a y step.
   - **(c)** For "distant" (l_tile ≥ max level), TEXEL1 read the tile *after* the max level (a stale descriptor). Now
     both texels come from tile base + max, with LOD_FRACTION 1.
   - **(d)** LOD levels were capped at 2. Now 6 tiles are bound (levels 0..4 + 1).
2. **Null-zone writer** (null+0x16 byte |= 4, which reads as null+0x14 = 0x400):
   - The write is `arg0->unk16 |= 4` in **func_15013D38** (game_40490.c), with arg0 = NULL.
   - func_15013D38 is reached from **func_1501396C** through `D_80082ECC[idx]`. That function declares the pointer
     `void (*)(void)` and calls `func()` with no argument. On N64 a0 still holds arg0 (the record) at the `jalr`. In the
     port the icall passes 0 (IR: `call void @__icall.1b33b86cd9f1(ptr %15)`, no arguments).
   - So the producer is **not a stub returning NULL**. It is the same missing-argument class as P75's func_1503BCAC. The
     stubs P75 suspected (func_150156F4, func_151BEE00) are only the neighbours. func_151BEE00 is the next call, and it
     gets garbage `pos` read from the null zone.
   - No guard was added: it does not crash. **Fix for the port branch:** `void (*func)(struct16 *)` + `func(arg0)` in
     func_1501396C. Check byte identity or put it under NON_MATCHING.
3. **func_150D1D20 gate:**
   - The backdrop callback is `D_80089578[header +8]` in func_15110420 (game_eu_13DC30.c). The table is at D_80089578
     (game data ROM 0x22E7F8): [func_15110948, func_150FA030, **func_150D1D20**, func_15110B80, func_15112074]. Level 0
     has mode 2.
   - The call needs `handle = func_15110E44(x, y, z, yaw) != 0`. For level 0, func_15110E44 returns **0 when player
     y < 1600 and the camera angle > 26**.
   - Runtime (`?p78sky=32`, Chrome): before the warp the angle is 13-18 (handle ≠ 0). After the 0x2C round trip the
     player is at y 289-410 with angles 27-47, so handle = 0 and the backdrop is skipped.
   - This is the game's own rule (C, NON_MATCHING), not a stub effect. D_800C3682 stays 0.

## 1. Per-material dump (`?p78tex=N`)

New in gfx_f3dex2.c. For gfx task N it logs (node too, no GL needed):
- **at every state change before triangles:** othermode, combiner, G_TEXTURE, and the tiles base..base+5 (fmt siz line
  tmem pal cms / cmt mask shift, tile size in texels);
- **once per distinct (TMEM generation, tile):** the decoded texels as `[p78hex]` rows;
- **at every G_VTX of a textured draw:** the raw Vtx records (`[p78vtx]`);
- **at each flush:** the batch's texel density per N64 pixel (affine screen gradients, the RDP LOD metric), plus the
  gradients and vertices of big triangles.

`python3 port/tools/p78tex.py LOG OUTDIR` turns the hex dumps into PNGs.

Findings (node task 400 = `p78/boot_tex400c.log`; Chrome task 470 = `p78/dump/chrome.log`, the ditch / field after the
round trip):

| material | othermode / combiner | tiles | density (texels / N64 px) |
|---|---|---|---|
| level LOD | 19AC3F (2-cycle, TL_LOD, persp, TT_RGBA16, bilerp), cc 26A004/151092FF = lerp(T0, T1, LOD_FRAC) x shade | G_TEXTURE level 4, tiles 0..4 = 32x32 → 2x2 (or 64x32 → 4x2), shift k, ul 256 >> k, LOADBLOCK dxt 0 | grass near ground 0.23-0.43, ditch lip 0.066 |
| level 1-cycle | 08AC3F, cc 121824/5531FEFF = T0 x shade | tile 0 only (tile 1 is a stale descriptor) | 0.3-1.5 |
| Conker | 19AC3F/04D1x078, cc 26A080, level 2-3 | RGBA4-as-CI 32x64 + mips | 5-30 (minified) |

- **Decode checked.** The stone wall (64x32 CI4 + 4 mips) and the grass (32x32 CI8 + 4 mips) decode cleanly at every
  level. Dropping the odd-row TMEM xor gives visible comb artefacts, so the xor is right.
- **UVs are planar.** For example s = 255.5 + x / 9.38 and t = 255.5 - z / 9.38 on the arena floor. The ditch lip has
  45 world units of height mapped to 1.2 texels against 36 texels per 314 units horizontally.
- **The blur is the bilinear (3-point) magnification of these tiles.**
