# Session P4: wasm memory model (branch `port-web`, 2026-10-22)

Goal: design and prototype how the N64 data, which is full of absolute addresses, lives in wasm
memory. This was the blocker before rendering. Design and reasons: **`docs/port/MEMORY.md`**.
Everything is under `port/` and `docs/port/`; no game `.c` file, shared header or shared build file
was changed, so the matching N64 build is unaffected. `verify_all.sh` was not needed.

## Result

- **Model (hybrid c):**
  - The N64 layout is kept in two mirror arrays: `n64_rdram` (8 MB, KSEG0/KSEG1) and `n64_seg16`
    (TLB 0x16). Data symbols become labels in them.
  - The three data segments are loaded from the user's ROM at boot, `game_data` through a raw
    DEFLATE inflater.
  - **5354 pointer words** are relocated: 3244 become wasm function-table entries, 2110 data
    pointers, 42 of which into C-defined objects.
  - **Virtual big-endian** game memory (word-swapped storage, lane xor) is applied by an LLVM IR
    pass to all 713 game TUs.
  - The 1635 zero-filled data stubs are gone. 14 remain, for absolute low symbols: ROM offsets used
    as `&sym`.
- **Calls:** one canonical wasm signature per function. 791 call sites are rewritten, and link
  signature warnings went from 288 to 1. 5 "absolute" names (US names at EU addresses) now forward
  to their C bodies instead of being stubs.
- **Boot:**
  - The PC `func_15007830` (`port/boot/game_entry.c`, translated from the asm) runs the whole init
    sequence. It enters the main loop with the state machine read from the real jump table in ROM
    data (`jtbl_80095DE0`: `1500793C 15007944 15007970 1500797C 1500793C`).
  - State 5 runs once (`func_151E582C`, `func_15017498`, `func_15007A70` with the mixed-width
    `lh +2` reads, `func_15007B3C`). After that the loop runs in state 0, one pass per frame (544
    frames in a 10 s node run, 375 in Chrome), with 23 distinct stubs hit.
  - Rendering does not happen yet: `osSpTaskStartGo` gets no tasks, because the frame-building
    functions are asm.
  - The null zone shows 6 words written through NULL pointers, from stubs returning 0.
- **Endianness test: PASS in node and in headless Chrome** (below).

## Endianness test (`port_memtest`, `port/boot/game_entry.c`)

The expected values are decoded with big-endian semantics in Python, straight from the ROM bytes
(`n64mem.py` → `memtest_expect.h`), independently of the wasm loader. This is the difftest idea:
N64 semantics as the oracle. The functions under test are the real converted C bodies, compiled
through the vbe pass:

| function (TU) | reads | rows |
|---|---|---|
| `func_1509CE40` (game_eu_CA630.c) | `D_800877D0[i].unk8`, a `u16` in a 0x14-byte struct in `game_data` | i=0..7: 0x0029 |
| `func_1509CE60` (game_eu_CA630.c) | `*(u16 *)(&D_800877D0[i] + 0xA) & 0xFFF` | 0x000 / 0x006 |
| `func_1509CE88` (game_eu_CA630.c) | `.unk4` `s32` | 0xA0000002, 0x60000000, 0x20000003.. (not relocated: below the D window) |
| `func_1509CE20` (game_eu_CA630.c) | `.unk0`, an `s32` that holds a pointer | 0x8009EC04 → relocated to the mirror; mapped back it equals the N64 value |
| `func_15041770` (game_eu_6EDC0.c) | linear search of the `u8` table `D_80084C60` | 10 characters, including not-found = 0x50 |
| inline | an `s32` written by game code, read as `s16[1]` (`lh +2`), as `u8[0]`, then `u8[3]` stored and the `s32` re-read | 0x5678, 0x12, 0x1234569A |

All 45 checks pass in node and headless Chrome (`[memtest] PASS (0 failures)`). For comparison,
a plain LE build reads `unk8` as 0x2900 from the raw ROM bytes, or as 0xD000 from word-swapped
storage without the lane xor, and reads `lh +2` of 0x12345678 as 0x1234.

## Known gaps and next steps

1. **Indirect calls** are not signature-normalized. `call_indirect` traps when a C function-pointer
   type differs from the target. Type the tables from their call sites, or use
   `-sEMULATE_FUNCTION_POINTER_CASTS` as a stopgap.
2. **Address constants in C and pointer masking** (`0x80xxxxxx` literals, `K0_TO_PHYS`). They need
   `port_n64_to_wasm`/macros. A grep plus a force-included macro set is next.
3. **Bitfields:** 152 declarations, mostly the GBI/ABI headers. `game_eu_1207F0.c` needs a
   `#ifdef PORT` reversed layout.
4. **`va_arg` of `double`** in game varargs functions is half-swapped.
5. **`OSThread` `u16` fields** written natively by `pc_sched.c` should use `vbe_st16`.
6. **Pointer-scan review:** cross-check the D list with `datarefs.py` and code xrefs, and add an
   override list for false positives or negatives.
7. **Absolute low symbols** (`D_10029400` and 13 more, ROM offsets used as `&sym`) are still zeroed
   stubs. Give them their values with a force-included `#define` for the users (Phase 2B).
8. **The 2 duplicate definitions** with different arity (`corrupted`, `func_15042D94`). The latter
   is hidden by normalization.
9. **Rendering:** Fast3D on `osSpTaskStartGo` (PLAN 3.3) once the frame-building functions are C.
   Read display lists with plain 32-bit loads, vertices with `vbe_ld16`.
