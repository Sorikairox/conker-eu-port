## 1. Segment ambiguity: `-sGLOBAL_BASE=256MB`

Decision, cost and alternatives: `docs/port/MEMORY.md`, "Address space and RSP segments". In short:

- every wasm data address is now `>= 0x10000000` (`PORT_WASM_BASE`, `pc_mem.h`);
- in a display list, `0x01000000..0x0FFFFFFF` is always a segment address, so the renderer
  (`gfx_addr`) needs no heuristic;
- an address in a segment that was never set gives 0 and is counted
  (`[sp] ... bad/unset-segment addresses`);
- segment bases `>= 0x80000000` now go through `port_n64_to_wasm`;
- `port_mem_load` checks the invariant and logs the layout;
- `port_mem_null_report` scans only the first 16 MB of the zone, so it doesn't fault in the rest.

Measured with node: maxRSS 1488 → 1496 MB (noise). Boot, memtest, icalltest and the gfxdemo frame
statistics are unchanged (2029 commands, 925 triangles, 48 from TRI4). The open risk is 32-bit
browser processes, which need a contiguous 352 MB, and an iOS device test. The fallback plan is
in MEMORY.md.

## 2. PC overrides: `port/boot/pc_overrides.c`

This file is compiled through the vbe pass, like the other `port/boot` TUs. Its strong definitions
replace the weak asm stubs; the game `.c` files keep their GLOBAL_ASM.

- **`func_100061F8(lo, hi)`:** it sets Index = i, EntryHi = 0x80000000 and EntryLo0/1 = 0, then
  `tlbwi` for i = hi..lo. That *invalidates* TLB entries lo..hi. On the PC it is a no-op that
  returns 0: there is no TLB, code is native, and the 0x16000000 data is the static `n64_seg16`
  mirror. It was the #1 per-frame stub (542 calls in 10 s).
- **`func_150ADA20`:** guRandom on a `u64` seed `D_80088950`, transcribed instruction by
  instruction. It matches P5's formula:
  - `t = x<<63>>31 | x<<31>>32`;
  - `t ^= x<<44>>32`;
  - `x = t ^ (t>>20 & 0xFFF)`;
  - return `(s32)x`.

  Self-test `port_overrides_test()` (run at boot): three steps from seed 0x0123456789ABCDEF give
  780B1177, 0D12F86A, A90FD6A5 (values computed in Python), and the stored seed is checked. This
  also exercises the vbe 64-bit load/store. Result: `[overrides] guRandom PASS` in node and Chrome.

## 3. Texture ids

**The engine resolves them in place when it loads a model**, in asm:

- **`func_1510D3E0(Gfx *dl, s32 only_seg0, s32 a2, s32 a3, s16 **used)`** (game_eu_13A8A0, asm,
  181 lines) is the DL walker. It runs over the commands up to `0xDF` (G_ENDDL). For each
  G_SETTIMG (opcode byte `-3`) whose `w1` has a top byte below 0x06 and segment nibble 0:
  - `id = w1 & 0xF03FFFFF`, `flags = w1 >> 22`;
  - `w1 = func_1510D66C(id, &size, a3, a2)`;
  - if `flags & 1`: `w1 += size - 0x200` (256-colour TLUT at the end of the texture);
    if `flags & 2`: `w1 += size - 0x20` (16-colour TLUT);
  - it optionally returns the list of ids used (bitset → `u16` count + ids); the return value is
    0 if a texture is missing.

  So `0x00000ED0` is the texels of texture 0xED0, `0x00400ED0` its 256-colour palette, and
  `0x00800C1B` the 16-colour palette of 0xC1B.

  Callers (all asm): func_150031EC, func_150039E0, func_15030100, func_1503D210, func_1503DD8C,
  func_15133C18, func_1513B5E0, func_1518403C, func_1518C900, func_151EE704.
- **`func_1510D66C(id, s32 *size, s32 prio, s32 ref)`** (asm, 180 lines) is the texture cache.
  - The id must be below 0x1E54.
  - `D_800B1268[id]` holds the resident address, `-1` for not loaded, or `0x80000000` for none.
  - On a miss it computes the ROM offset with `func_1510D8F4(id)` (**C**:
    `&D_1A3B40 + sum D_800920D0[0..id)`), allocates with `func_10003C6C` and DMAs with
    `func_10004514`. It then allocates `D_800B8BB8[id]` bytes, inflates with `func_10006530`
    and frees the temporary buffer with `func_10004074`.
  - It keeps priority and refcount bytes in `D_800BC860` and `D_800DA388`.
  - Its other callers are DL builders such as `func_150954E4` (texture rectangles: an address below
    0x10000000 is an id) and `func_1503DF2C` (C, material tables).
- **`func_1510D984`** (asm) ages or evicts the cache. `func_1501878C` calls it every frame.

**The texture bank, checked in Python against the ROM:** texture *i* is an rzip file at ROM
`0x1A3B40 + sum D_800920D0[0..i)`. `D_800920D0` is a `u16` compressed-size table in game_data;
the sizes sum to 9496318, so the bank ends at 0xAB223E. Each file is a BE `u32` size followed by raw
DEFLATE. Texture 0xED0 is at 0x6F1618 and inflates to 768 bytes: 256 bytes of CI8 texels and a
512-byte TLUT, which matches its DL (LOADBLOCK 128 words, LOADTLUT 256).

**Port gap found:** `func_1510D8F4` is C, but `&D_1A3B40` is one of the 14 zero-filled "ROM offset
used as &sym" data stubs (`port/stubs/data_stubs.c`). In the port it evaluates to a wasm address, so
the PI DMA would read the wrong ROM offset. These symbols need to become absolute values in the
port: the vbe pass could replace `ptrtoint @D_xxx` with the constant from `stubs_report.txt`. That
is needed before game-driven texture loads work.

**Conversion priority for P7's successor (port branch):** func_1510D66C, then func_1510D3E0, then
func_1510D984 (already #27 in the measured list below). The DMA and inflate helpers
func_10004514, func_10006530 and func_10004074 are on the boot path too.

**Viewer (`port/gfx/gfx_demo.c`).** `tex_patch_dl()` is a PC copy of func_1510D3E0's rule, applied
once when an asset loads. It follows `G_DL` into the model file (segments 0/1) and loads textures
on demand from the bank. It reads the size table from its own inflate of game_data, so it works
before `port_mem_load` too. Resolved `w1` values are wasm pointers (`>= PORT_WASM_BASE`).

- Result: 57 of 81 texture-id commands per frame are resolved (24 are left: these are in lists the
  viewer doesn't walk, or in segment-8 material DLs, which are empty here).
- Screenshot: the gadget (top left, green body, red display, real CI8 palette), the tyre (bottom
  left) and the face textures on the heads.

**Renderer fix:** 4- and 8-bit texels are read as CI when TLUT mode is on, as the RDP does.
RGBA4 and RGBA8 don't exist; Conker's model DLs use them for CI textures and let the engine's material DL
turn TLUT mode on, so the renderer reads them as CI too. Before this fix they drew magenta or black.
The heads are still partly black: their combine, colour and TLUT state comes from the engine's
segment-8 material DLs, which the viewer leaves empty.
